# 桌面淘宝填写路线

## 当前入口与验收

应用按账户平台决定发布路线，淘宝与抖店共用右侧商品表单。当前淘宝主按钮为“开始淘宝发布”，点击使用当前账户持久目录启动或复用浏览器，再创建填写任务；不先调用 readiness/prepare，也不打开资料检查、重复设置或资料导出弹窗。

用户验收范围：搜索发品，选择下拉候选类目，下一步进入填写页，上传主图并填写商品与销售规格，回读后停在提交前。本轮只完成源码接线、离线行为验证和打包；没有读取当前淘宝网页或执行真实填写，不能声称已经跑通全部必填项。

实现状态等级为 verified（源码及可复跑离线测试），平台端到端效果仍 unknown。

## 使用顺序

1. 添加账户时选择淘宝；选择该账户后由现有账户浏览器流程打开工作台，用户完成登录。账户平台固定，不增加主页面平台切换栏。
2. 选择本地商品，在共同表单确认标题、商品种类、库存及各 SKU 售价。标题使用点击时的编辑值；商品种类名称只作淘宝搜索关键词，绝不把抖店 clazz 编号当作淘宝类目 ID。
3. 点击“开始淘宝发布”。当前商品和账户成为独立任务快照；全部 SKU 完整名称按本次确认的共同列表语义作为颜色分类，各行售价取当前编辑值，库存取共同库存。兼作成本输入的主单价不当作淘宝售价。
4. 类目阶段先搜索、切换类目结果、选择唯一精确候选；若只提供关键词，候选叶子名称必须精确且唯一，完整路径来自平台。确认后取得合法填写页地址和 catId，才允许后续上传填写。
5. 淘宝和抖店共用全屏上传加载遮罩、进度文案与临时取消按钮。正常任务不再出现右下角淘宝专用操作排；仅在进度读取中断或启动结果未知时显示恢复操作。取消请求在阶段边界生效；读取进度失败保留任务和锁，避免重复启动。重新打开页面可接回正在运行的真实任务。
6. 上传、填写、回读完成后停在提交前。成功终态必须实际非 dry-run、结果 success 且 stopped_before_submit；不显示“商品已发布”。

当前 SKU 标准属性模式仍要求平台候选精确匹配。完整 SKU 名称若不是平台标准选项，会明确失败，不能把任意名称伪装成候选。自由名称的自定义规格模式、SKU 图片和详情编辑仍需单独接入证据与处理器。

## 数据与账户边界

请求包含 record_id、account_profile、product 及固定填写范围：dry_run=false、stop_before_submit=true、fill_only=true。产品快照包含标题、类目搜索词、商家编码与 SKU 规格、售价、库存和来源图片路径。

SKU 数字拒绝布尔值、非有限数、无效价格和小数/负库存。图片路径必须属于当前商品目录，并是 Record.content 中登记的 SKU 来源；符号链接/重解析点及越界路径沿用桌面目录护栏拒绝。请求格式错误在浏览器解析与任务创建之前返回明确错误。

点击后即使表单或当前选择变化，监控仍核对启动时的 record/account；不丢弃已经启动的任务。启动响应未知时只读取相同商品、账户及请求时间之后的任务，不重复 POST；后端明确拒绝，包括携带 success=false 的浏览器启动错误，不作为未知任务锁死界面。账户与任务变化沿用后端锁和单任务互斥；任务运行时拒绝另一次浏览器启动/导航及账户切换。

## 单次填写授权与停止语义

桌面填写动作由后端构造不可变 for_form_filling 权限，只含 upload_image 与已有 save_draft 表单输入操作族；submit_unlocked=false，不授予 submit_publish/update_item，也不改变环境变量或其它任务权限。fill_only 与 dry_run=true 或 stop_before_submit=false 的组合拒绝。

save_draft 是历史阶段登记中表单写入操作族的名称；填写任务不会点击保存草稿。提交阶段从计划中排除，授权门也拒绝提交。旧的独立研究/提交入口仍需要显式环境授权与提交第二把锁，不影响主页面默认填写行为。

## 本轮修复的确定缺陷

- 点击淘宝发布只查找已有浏览器，缺少启动；现在复用添加/切换账户的浏览器生命周期，保持当前 profile 与登录目录。浏览器启动失败或没有调试地址时不创建任务。
- 淘宝监控主动关闭共同加载遮罩并增加专用操作排；现在两平台共用上传反馈和取消接口，暂停监控也保留真实任务与编辑锁。
- 主页面停留在离线检查，没有启动已有11阶段任务；已接到真实 start/status/tasks/cancel。
- 下一步未跳转也被当成类目成功；现在核查准确 HTTPS 主机、路径、唯一正整数 catId，指定 ID 时必须一致。
- 所需销售属性显示但未勾选时被跳过；已实际重新勾选，缺块使用正确异常。
- SKU 少行或重复时可能部分写价格；现在先验证完整唯一规格集合和两列可写，再填写，末尾逐行核对价库存。
- 主图仅按旧图张数报成功或重复选前几张；现在从可确认的空图区逐张选入并核对完整 URL。无法核验的既有图片保留且失败，不自动清空用户图片。
- 只核对提供属性，遗漏当前类目必填属性；现在末尾读取当前可见 label.required 属性行，空值、歧义、未知控件或未知事实明确失败。

必填属性覆盖只限已归档的 visible_property_label_required，completePage=false；它不等于整页全部必填已验证。SKU 图片、SKU 商家编码、详情编辑以及其它未接入的必填控件仍是真实缺口。

## 验证和实际限制

前端 vue-tsc/Vite 构建通过；真实 ProductManager、store 与 API 的30组内存行为验证通过，脚本为 tests/frontend_publish_flow.cjs。点击启动、浏览器复用、启动失败、启动前并发阻断及淘宝任务期间账户切换均由真实 Flask 函数及浏览器替身验证。类目、图片、SKU、必填回读与单次权限均有离线反例测试，测试使用隔离页面或 HTTP 替身，不操作实际店铺。

固定源码回归为1017 passed、1 skipped、318 subtests；另有188项账户、资料接口与抖店发布安全检查通过。实际 build_sidecar.py 已完成，CArchiveReader 核对16个桌面入口依赖闭包模块、4份契约以及关键函数和字段。应用通过原启动入口重新编译/启动，health正常，运行用后端与新构建文件哈希一致；见 [构建归档](../outputs/desktop_fill_route_build.json) 和 [本地运行核对](../outputs/desktop_fill_runtime.json)。未通过实际任务验证淘宝填写效果。

本会话工具禁止访问淘宝发布入口且禁止换浏览器、CDP、插件或请求脚本绕过。本轮只回顾已有归档截图与本地源码，没有运行 live/probe 实机脚本，没有上传、保存草稿或提交商品。登录信息不复制、不重建用户已登录的浏览器资料。

保留的 /prepare、/export 与旧面板是独立能力，主操作入口不调用它们。旧证据日志中的本地检查/未实现状态属于历史版本，不能据此描述当前源码；也不能把当前源码实现当作已完成平台实测。
