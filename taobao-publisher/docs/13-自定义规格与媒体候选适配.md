# 自定义规格与媒体候选适配（2026-10-04）

本轮继续原完整目标：共同前端点击上传后，写入采集商品及全部必填项，回读确认并停在提交前。本轮没有操作真实淘宝工作台，没有读取账户身份、保存草稿或提交商品。

## 实现与证据边界

新增 `taobao_publish/form_adapters.py`，接入现有流水线。以下都是 **candidate 平台适配**，不是已经验证的淘宝控件事实：

| 环节 | 实际已实现 | 尚需确认的淘宝事实 |
|---|---|---|
| 单层自定义规格 | 切换模式；只写唯一原生文本框；完整中文名称逐行回读；确认创建后按完整规格匹配价格库存 | 自定义模式切换后，名称行、输入框及加行按钮的真实结构 |
| SKU 图片 | 图像内容摘要命名；图片空间精确文件名和完整 URL；逐条规格绑定；抽屉和最终表格均回读 | 单条规格的图片入口、图片卡片名称控件、最终表格图片结构 |
| 宝贝详情 | 准备图片后按输入顺序写入 HTML 编辑区；核对每个完整 URL 和顺序；已有内容保留并停止 | 编辑器类型及定位方式；目前只支持明确定位的原生 textarea/contenteditable |
| 共同前端 | 淘宝请求明确传 `sku_mode: custom`，无需新增固定控件；旧调用默认 standard | 当前店铺页面是否匹配此候选实现 |

生产 `contracts/selectors.json` 中的八个新条目均保留 `candidate`。处理器检查证据等级和来源；未达到 `verified` 时，在写阶段前返回具体 blocker。测试使用 `LOCAL_SYNTHETIC_FIXTURE_ONLY` 的独立契约，绝不修改生产契约，也不把测试通过计作平台取证。

Fusion 官方实现说明 Upload 可以由业务组件封装，基础组件的事件行为不能证明淘宝业务组件采用哪个输入框或编辑器。公开资料仅用于理解组件机制，未提供本店铺自定义规格和详情编辑器的结构证据。[Alibaba Fusion 官方代码](https://github.com/alibaba-fusion/next)、[官方 Upload 组件示例](https://mc.fusion.design/demos/comp_groups/%40alifd/next%401.19.x/upload?bgColor=%23000000&theme=%40alifd%2Ftheme-iceworks-light%400.1.0)。

## 数据与停止规则

- SKU 图必须通过 `skus[].image_path` 明确关联到具体规格，不能按图片数组序号绑定。孤立媒体意图阻断。
- SKU/详情图上传名带商品 ID、用途和 SHA-256 摘要前缀。记录完整摘要和完整远端 URL；相同内容可以复用，不按同名原图猜身份。
- 素材同名多命中、URL 不一致、未知已有名称/图片/详情、编辑器不唯一、控件禁用均失败；不对这类错误重新发送文件。
- 每次只执行一次图片选择，等待实际目标回读；滚动查询有界并等待列表渲染。
- 仅有绑定回执仍不足以成功：最后再次读取当前 SKU 表图片与详情编辑内容，发现后续操作改写即失败。
- 不执行保存草稿、提交按钮或编辑器私有 API。真实平台的 iframe/私有编辑器仍是缺口，不能猜方法。

另修复属性输入语义：没有显式类目属性覆盖值时，保留页面现有值并跳过属性改写，不再以空覆盖列表直接失败。最终 `label.required` 属性核对仍执行；属性必填缺值仍失败。覆盖范围仍明确为 `visible_property_label_required`、`completePage=false`，没有将其扩充为整页必填证明。

## 可复现离线验证

`tests/fixtures/candidate-form.html` 是人工构造的本地模型，不是淘宝 DOM 归档。`tests/test_candidate_form_adapters.py` 每次建立全新的 headless Chromium profile，只连接精确的本地 `file:` 页面；禁用外部域名解析，不复用用户 Chrome、登录态或 Cookie。

12 项验证通过：包含中文完整规格、逆序表格里的价格库存和图片对应、长 URL、详情顺序、未知已有文字/图片/视频/布局保护、contenteditable、重复编辑器、素材重名、控件禁用、最终图片 URL 改写、生产候选证据阻断等。上传服务器响应由夹具模拟，没有真实图片上传。处理器与浏览器 DOM 执行是真的，平台行为不是实测。

实际 Vue/Pinia/API 源码的共同上传流程 44 项通过；`npm run build`（vue-tsc + Vite）通过。完整相关回归、冻结包和本地部署核对结果记录在本轮证据日志及构建产物中。

## 完整目标仍未验收

本轮将三个“没有处理器”的缺口推进为“已有可证伪的候选处理器、等待真实控件证据”。现有工具对淘宝后台访问的拒绝没有变化，不能换工具、内部接口或连接方式取得相同页面内容。整页必填覆盖与真实提交前填完仍未验证。需要用户直接提供去敏结构，或工具访问策略明确允许该工作台的执行环境，才能核对候选并继续店铺实测；不要求密码、Cookie、验证码或再次登录。
