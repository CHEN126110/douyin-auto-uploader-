# 默认无品牌与素材内容身份

2026-10-04，用户明确要求品牌默认选择“无品牌”，流程与抖音上传体验保持一致。本轮修复类目页的品牌交接，并收口正在开发的图片身份验证。共同前端没有增加品牌配置区、账户资料检测或固定淘宝按钮区。

## 品牌规则与阶段交接

原处理器仅在 `item.props` 中存在品牌时才执行选择；类目页要求品牌但商品快照没有品牌时，直接返回 `BRAND_REQUIRED`，导致选完类目无法进入下一步。

当前规则：

1. 商品明确提供品牌时使用该值；提供互相冲突的品牌值则拒绝，不任选一项。
2. 没有提供品牌时使用用户指定的“无品牌”。这个默认值来自用户要求，不是对商品事实或平台选项的猜测。
3. 存在品牌控件或下一步尚不可用时，打开唯一可见品牌行并精确匹配选项。只接受“无品牌”和已知原文“无品牌/无注册商标”这两个无品牌写法；其它明确品牌只精确匹配自身。
4. 候选缺失、重复或禁用时不点击下一步。品牌点击后只等待下一步按钮可见、可用，不重复点击品牌或下一步。
5. 成功进入填写页并核对 `catId` 后，把实际选中的品牌原文带入本次商品属性。填写阶段若读到同一品牌，就保留当前选择；最终回读仍核对它。

这是软件规则与交接的 `verified` 本地证据，不能代替当前淘宝页面的实机验证。没有放宽授权、候选控件或整页必填的证据要求。

## 素材身份与回填

主图、SKU 图和详情图使用商品 ID、图片用途及文件内容摘要形成上传身份；主图同时保留槽位序号。同一商品同名图片改过内容，会得到新的上传名，避免复用图片空间中的旧图；相同内容放在不同主图位时，仍保留指定数量与顺序。已不再使用的旧商品名前缀函数已移除。

上传前先复制并验证整批素材快照，再打开上传入口。预期摘要与快照内容不同会返回 `MEDIA_SOURCE_CHANGED`，该批文件尚未发送。上传只消费快照，正常返回、平台拒绝和异常都清理临时副本；用户原图不被改名或覆盖。

主图选择采用完整文件名边界匹配，避免把 `图片.jpg.backup` 当作 `图片.jpg`。虚拟列表滚动后等待渲染，再读取候选；候选不唯一、图片 URL 无效或选择控件禁用时停止。每次选入后核对完整 URL 及顺序，图片张数变化不能独立证明选对了素材。

这些处理器仍受生产契约的证据检查约束；素材识别、自定义规格、SKU 图片入口/表格图片和详情编辑器共八个生产条目仍为 `candidate`，本地模型不会提升它们。

## 可复跑的本地证据

`tests/test_default_brand_and_media_content.py` 包含 24 项：默认品牌、已知原文、显式品牌、不可选/未确认品牌、品牌最终回读、图片内容变化、批量快照、临时副本清理、文件名边界、虚拟列表渲染，以及主图 URL 延迟和不匹配。

`tests/test_category_first_pipeline.py` 保留 20 项阶段交接验证。真实隔离 Flask 保存/启动接口、工作线程和原始类目处理器在人工页面上执行搜索、类目点击、品牌选择与下一步；当前生产契约模型在图片阶段明确停止，图片上传为零。测试契约可以继续执行填写和回读，整页必填覆盖仍为 `partial`。

浏览器使用独立临时 profile 的 headless Chromium，外部域名解析禁用，只打开 `file:` 人工模型。浏览器启动、会话事实、导航地址及平台上传服务器是明确的测试边界替身。没有从工具启动真实淘宝任务，没有保存草稿或提交商品。

现有工具对实际淘宝后台的访问限制没有改变。当前修复不证明真实店铺已通过品牌步骤，也不声明整条发布目标完成。
