# 先选择类目与下一步的阶段开发

2026-10-04，根据用户要求，点击发布后先执行选择类目和下一步，再按页面顺序推进后续开发。

## 当前执行顺序

共同前端保存本次编辑快照并启动绑定账户的浏览器，然后执行：

1. `session`：连接浏览器，读取当前页面状态，允许从类目页开始。
2. `precheck`：确认本地商品、页面状态及本次动作授权。后续控件缺口按阶段记录，不阻止类目流程。
3. `select_category`：输入共同类目下拉中的名称，搜索发品，切换类目结果，唯一匹配候选，点击文本，回读完整面包屑，点击“确认，下一步”，核对填写页地址及唯一正整数 `catId`。
4. `upload_images` 及各填写阶段：每个阶段在打开页面或写入前检查自身所需控件；缺口在本阶段明确报错。
5. 最后回读，保留提交前停止要求。部分区域通过不能当成整页必填完成。

基础数据或授权本身不成立时仍然停止。类目候选缺失、重复、品牌要求未满足、下一步禁用或未进入正确填写页时也会失败；不选第一条、不编造品牌、不重复点击下一步。

## 控件依赖范围

| 阶段用途 | 检查的控件 |
|---|---|
| 预备规格/详情图片 | 精确文件名识别 `media.exact_filename` |
| 自定义规格与对应图片 | 自定义模式/行/输入/新增，加规格图片入口、表格图片及素材识别 |
| 详情填写 | 详情编辑器与素材识别 |
| 最终媒体回读 | 对应表格图片及详情编辑器 |

控件来源仍须 `verified` 且具有证据来源。各处理器提取配置也按用途限定；例如预备图片不依赖详情编辑器是否实现。未指定对应规格的图片在任何图片上传前报错，缺少媒体绑定回执时优先报告尚未完成。

预检在 `deferred_adapter_blockers` 中记录后续缺口，流水线报告保留该字段。实际阻塞阶段的 `blockers` 只列当前阻止执行的原因。检查在统一执行器和可直接调用的阶段入口均生效，授权及取消边界保持有效。

当前生产八个控件仍为 `candidate`；它们不再提前拦住类目阶段。以当前商品意图，完成类目和下一步后会在图片阶段因素材身份识别尚未确认而停止，不会先上传主图再报告这项缺口。

## 本地流程证据与边界

`test_category_first_pipeline.py` 包含 20 项验证。九个浏览器场景通过真实隔离 Flask 保存/启动接口、工作线程和原始类目处理器，执行人工页面上的原生输入事件、搜索、结果切换、候选点击、异步面包屑及下一步按钮。其它用例验证控件范围、非法用途、素材对应关系和写入前拦截。

正向生产契约场景的阶段为 `session:ok → precheck:ok → select_category:ok → upload_images:failed`，下一步只点击一次，图片上传调用为零。完整本地契约场景继续跑完十个提交前阶段，仍保持整页验证为 `partial`。

反例覆盖：候选歧义/缺失、品牌必填、搜索禁用、下一步后仍留在类目页、无效 `catId`、下一步后取消，以及未关联规格图。共同前端也消费该真实本地任务结果，显示图片阶段失败，不跳设置页，不显示完整填写成功。

浏览器为新建独立 profile、外部域名解析禁用的 headless Chromium，始终打开 `file:` 人工模型。浏览器启动、会话元数据和导航地址为明确的测试边界替身；模型 `href` 只是字符串，不发起淘宝导航。当前工具对实际淘宝后台的访问限制没有改变，本轮没有操作真实店铺。

产物：[本地类目任务结果](../outputs/category_first_pipeline_handoff.json)。它证明软件阶段交接，不证明实际淘宝页面已经通过。

## 后续品牌规则（E-162）

按用户指定，商品没有提供品牌时默认选择“无品牌”，也识别已知原文“无品牌/无注册商标”。类目阶段先选品牌并等下一步可用，成功后把实际值带入填写和最终回读。上述“品牌要求未满足”现在指真实候选无法唯一选择或下一步未确认可用，缺少商品品牌属性本身不再成为阻塞。详见 [默认无品牌与素材内容身份](17-默认无品牌与素材内容身份.md)。
