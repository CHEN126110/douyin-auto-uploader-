# 图片回执直达与目录跳转优化

日期：2026-10-08。用户反馈：图片已上传且可见，选图时仍频繁在文件夹间跳转。

## 已定位的原因

1. `verified（源码与隔离模型）`：JS 目录定位支持路径后缀，Python 却用完整列表逐字比较。“商品/主图”和“全部图片/商品/主图”指向同一节点时，Python 仍逐级走父目录。反例中连续三次定位已选目录产生六次点击；修复后为零次。
2. `verified（源码）`：协议上传前扫商品子树，上传后先查当前目录、再重扫子树。即使回执已有图片 ID、URL 和已确认的目标目录，也会提前访问主图、SKU、详情目录。
3. `verified（源码与隔离模型）`：目录就绪判断要求观察列表签名变化；目标图片已到位但未观察到变化时，仍会等待并触发切走再切回。新增目标图片 ID 与 URL 的直接就绪判据；没有精确目标时保留通用列表加载检查。
4. `verified（本地交接测试）`：`UploadedImageReceipt` 原来未保留 `picture_id`。已在上传端、准备回执和选图计划间传递图片 ID，兼容没有该字段的旧回执。

## 当前处理方式

协议路线先确认用途目录 ID，复用原上传钩子的“内容摘要＋目录 ID”去重机制，拿到完整上传回执后按用途直接选图。主图阶段不预读 SKU 或详情目录；其它用途在各自阶段进入目标目录。

已渲染且唯一的目录节点直接定位；路径前缀统一后，当前目录已选中就不重复点击。图片 ID 与回执 URL 对上后直接选择，仍保留槽位/规格/详情内容的最终回读。错误 ID 与 URL 组合在点击前拒绝，不靠目录刷新掩盖身份错误。

准备回执只记“已上传、未定位”，不提前写入猜测的目录索引；实际选择并回读后再记“已定位”。旧 DOM 上传路线仍需要从图片空间取得定位回执，图片管理的完整文件树读取能力保留。

主图当前实现仍按单个槽位逐张回填。本轮减少的是重复目录导航、全树预扫和无必要刷新，没有通过改写页面私有状态直接塞入图片 URL。

## 验证范围

本地测试使用新建、无账户的 headless 浏览器和人工 HTML，验证路径别名、目标已显示、旧目录卡片延迟消失、错误图拒绝、主图阶段只访问主图目录、图片 ID 交接、原上传路线及实际本地 HTTP 工作线程交接。

测试与部署详情见[验证数据](../outputs/media_direct_lookup_validation_20261008.json)。真实淘宝页面的当前 DOM 和耗时仍属 `candidate / unknown`：当前工具的站点访问限制没有解除，本轮没有用其它连接方式绕行，也没有保存草稿或提交商品。
