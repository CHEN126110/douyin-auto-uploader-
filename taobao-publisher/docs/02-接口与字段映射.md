# 02 · 接口与字段映射

> 本文说明「本地商品资料」如何变成「平台载荷」，以及**为什么现在这一步必然失败**。

2026-10-03 补充：[淘宝发布流程与字段清单](09-淘宝发布流程与字段清单.md) 按当前归档画面列出商品级一口价、总库存和导购标题的模型缺口。界面字段存在不等于对应写字段已取证。

## 1. 三层数据模型

刻意画死三层边界，目的是**让平台字段名只能出现在一个地方**。

```
SQLite record 行 + 采集目录
        │  local_source.py
        ▼
   LocalProduct        ← 本地资产投影，不含平台字段名
        │  mapping.build_publish_item()
        ▼
   PublishItem         ← 平台无关的发布意图，仍然不含平台字段名
        │  mapping.build_platform_payload()  ← 过契约门
        ▼
   平台载荷 dict        ← 字段名**全部来自** contracts/field_mapping.json
```

**为什么这么分层**：淘宝写接口的字段名一条都没实证。如果把 `pid` / `sku_prices` /
`postage_id` 之类直接写进 dataclass，后人会自然而然把它们当成事实，然后照着写代码、
写测试、写文档。分层之后，`taobao_publish/` 里**搜索不到任何淘宝字段名**——
它们只活在 `contracts/field_mapping.json` 里，且每条都带证据等级。

## 2. 本地资产：实测到的真实结构

本地数据来自 `sqlite.db` 的 `record` 表（`src/orm.py:21`）。**已实测**：

| 字段 | 实测值 / 说明 |
|---|---|
| `id` | 主键 |
| `name` | 形如 `ID-976666440420` |
| `title` | 商品标题 |
| `clazz` | **小整数**（实测为 `2`），是本地自定义类目，**不是**平台类目 ID |
| `shipping_template` | **中文名**，如「中通包邮」，**没有平台 ID** |
| `source_url` | 采集来源 URL（可能带一堆分享参数） |
| `content` | JSON 数组，元素为 `{dir_name, file_name, name, path, price}`，`price` 为 float（实测 61 条） |
| `status` / `type` / `repo` | 本地状态位 |

**没有库存字段**。这一点很重要：`sku.stock` 在契约里是必填，而本地取不到，
所以 `build_publish_item` 拿不到库存时留 `None`，`validate_skus` 直接产出阻塞项。
**不默认 0，也不默认 999** ——0 元/0 库存商品会被平台当成真实数据。

采集目录约定（对齐 `src/utils.py:2530-2830`）：

```
<商品目录>/
├── 主图/            主图_01.jpg、主图_02.jpg
│   ├── 750/         3:4 主图
│   ├── 800/         1:1 主图（优先）
│   └── 白底.jpg     （候选名：白底 / white / WHITE / 白底图）
├── 详情页/          详情图（备选名：详情图片）
├── SKU/             SKU 规格图
├── SKU_1x1/         src/whitebg 产出的 1:1 规格图
├── 白底图/          src/whitebg 产出的白底图
└── 白底图.jpg       目录根白底图（src/utils.py:get_white_pic 会自动取用）
```

`主图_01_1x1.jpg` 这类方图会被**排除出主图列表**（否则上传时会重复），
这条规则有单测覆盖（`tests/test_local_source.py`）。

## 3. 契约门：为什么现在写不出去

`contracts/field_mapping.json` 的核心是一条规则：

```json
"write_gate": {
  "rule": "platform_field 非 null 且 evidence.level 属于 [\"verified\"] 时，该字段才允许进入真实写操作。"，"route": "本条只约束 **mtop 协议路线**；DOM 路线不看 platform_field，它看 contracts/selectors.json 里的写关键选择器是否 verified（当前 30/30）。"
}
```

**为什么 `candidate` 不够**：本契约里大多数 `candidate` 来自**已下线的开放平台
老接口文档**。那些字段语义能帮我们理解新版 schema，但**不能证明**当前网页工作台
仍使用同名协议字段。拿 `candidate` 去写平台，等于拿猜测当事实——写进去就是脏数据。

当前证据分布（`python -m taobao_publish readiness` 实时输出）：

| 等级 | 字段数 |
|---|---|
| `verified` | 0 |
| `candidate` | 10 |
| `unknown` | 6 |

### 必填但不可写的 10 个字段

| intent | 卡在哪 |
|---|---|
| `item.title` | 工作台有标题填写环节（已实证），但控件选择器与提交体字段名未取证 |
| `item.category_id` | `record.clazz` 是小整数，不可当类目 ID；需实证类目查询接口 |
| `item.props` | 类目属性必须按目标类目动态查表，禁止硬编码 pid/vid |
| `item.sale_props` | 采集侧 ICE 有 `pid`/`vid`，但发布侧是否同套词汇未取证 |
| `item.sale_prop_values` | 目标类目的可销售属性值集合未取证 |
| `sku.price` | 字段名与**单位（元还是分）**未取证 |
| `sku.stock` | 本地无数据源，且平台字段名未取证 |
| `media.main_images` | 是否必须先入**图片空间**、接口形态、返回 URL 形态均未知 |
| `logistics.freight_template_id` | 平台只认 ID，本地只有中文名，且禁止按名硬匹配 |
| `publish.listing_mode` | 「立即上架」与「放入仓库」的协议差异未取证 |

## 4. 运费模板：这里有一条历史教训

本地只有模板**中文名**。最直觉的做法是「按名字猜 ID」，但抖店侧已经因此出过事故：

> `protocol-research-clean-20260505/scripts/fxg_protocol_v4.py:1063` 的注释记录了
> 因为硬编码 `300713474` 而**把商品发到了错误的店铺**。

所以 `match_freight_template` 比抖店 v3 更严：

1. 名称精确相等 → **唯一命中**才算成功。
2. 否则按「包含」匹配 → **命中多于一个即视为歧义，直接失败**。
3. 都不中 → 失败。
4. **任何失败都不返回默认模板 ID。**

匹配失败的原因是中文的，会直接展示给人看，例如
`运费模板「包邮」模糊匹配到 2 个候选，拒绝猜测`。

## 5. mtop 协议层

`taobao_publish/mtop.py` 提供：

| 能力 | 说明 |
|---|---|
| `parse_h5_tk` | 解析 `_m_h5_tk`（`token_expireTime`），**fail closed**：形态非法返回 `None` |
| `sign` | `md5(token&t&appKey&data)`，纯函数，有硬编码测试向量锁死 |
| `build_request` | 组装已签名请求（不发送），URL 形态与仓库读路径实测一致 |
| `classify_response` | 把 `ret` 分类成成功 / token 可重试 / 认证失败 / 普通错误 / **风控页** |
| `extract_h5_tk_from_set_cookie` | 从 Set-Cookie 取服务端下发的新 token（自愈路径） |

**它不发请求**。请求由浏览器内 `fetch`（带真实 cookie 与 TLS 指纹）或 CDP 发出——
这是读路径 `app.py:10906-10984` 已经跑通的形态，直接沿用。

`classify_response` 对**非 JSON 响应**特别处理：命中 baxia / x5sec / punish 等标记
即返回 `RISK_CONTROL_HIT`，流水线会立刻停手交人工，而不是重试。
**不做风控绕过，也不做自动重试。**

## 6. 入参契约

`contracts/publish_item.schema.json` 是 sidecar / CLI 的请求体形状，有意**不含任何
淘宝字段名**（有单测 `test_schema_contains_no_taobao_field_names` 守着）。

注意其中一条设计：

> 写操作授权**不在请求体里**，只从环境变量读。

这是防绕过的——如果授权可以从请求体传，那么任何能调到你 HTTP 接口的东西都能打开写入。
