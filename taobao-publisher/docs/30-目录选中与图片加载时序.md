# 30 · 目录选中与图片加载时序

## 本轮事实

上轮云端目录树及文件清单已经部署。本轮继续原目标时，检查“选中目录 → 读取文件 → 选图”的衔接。隔离浏览器模型把目录选中和图片替换分为两个时刻：先高亮 SKU，图库标记为加载中，250 ms 后才替换图片。

修改前四个反例均失败：新目录读到了上一目录的主图、空目录继承上一目录图片、已经选中的目录在加载中仍返回旧图片，以及图片地址相同的目录在加载尚未结束时就被认为读取完成。这证明的是本地代码时序缺陷，不是当前真实淘宝错误的唯一原因。

证据等级 `verified`（隔离模型）：[修改前失败记录](../outputs/media_directory_transition_reproduction.json)。同名但不同地址的图片不能据 URL 单独推断字节内容不同；本轮同步修正了相关错误措辞。

## 修复

1. 目录切换不再只确认左侧选中路径；图库有可见 `aria-busy=true` 或 `role=progressbar` 时，等待加载结束后再次核对路径。
2. 当前已选中的目录也要遵守加载状态；单张查询、整批查询、文件清单和选图共用同一加载读取器。
3. 文件清单或批量查询期间重新出现加载状态时，作废本次结果，不能把旧卡片归到新目录，或以空清单触发重复上传。
4. 加载超过限定时间明确返回错误并保留页面内容；不自动重传、不清空平台图片。隐藏的进度指示器不会阻塞读取。
5. 同名冲突错误文案改为“图片地址不同”，不再把 URL 差异称为已证明的图片内容差异。

## 验证边界

`test_media_directory_transition.py` 用新建隔离浏览器覆盖上述四个反例，以及超时、隐藏指示器、读取期间重新加载、整批查找与最终选图。目录、图库和上传服务仍为明确的本地模型。生产页面能否通过这些候选标记完整反映加载时序仍为 `candidate`。

相关错误回执测试也改为先提供有效加载状态，再执行原有选图判据，避免通过前置状态异常而误通过。JS 加载状态和分页动作均提取为命名构造器，构造器体检共54项/66次调用；调用与结果仍在原生产路径中，没有新增绕行的选图入口。

软件验证与部署结果记录在 `outputs/desktop_media_transition_validation.json`、`desktop_media_transition_build.json`、`desktop_media_transition_runtime.json`。此前 E-201 的结果是上一版软件证据，不能作为本轮新源码的验证结果。
