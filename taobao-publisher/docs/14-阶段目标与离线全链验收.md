# 阶段目标与离线全链验收

根据用户“调整一下目标然后再继续”的要求，本轮将项目工作分为两个阶段。原完整目标仍保留，不把真实店铺验收替换成离线通过。

持久目标工具当前只提供创建、读取和状态修改；已有未完成目标无法改写正文或替换。本文记录调整后的项目阶段目标，不能声称工具里的目标卡已改写，不能把旧目标虚假标记完成。

## 第一阶段：完成可审查的软件实现与离线全链验证

目标：保持共同前端，贯通保存当前商品快照、版本绑定、任务创建、流水线、主图、完整 SKU 名称及对应图片、售价库存、详情、当前账户运费选择、回读、进度和提交前结束的代码链路。验证只使用隔离数据及本地模型页面，平台边界明确模拟；发现联查问题继续修复并部署开发版。

验收条件：

1. 两平台共用原上传入口，不增加固定淘宝配置区、账户资料检查或重复设置页面。
2. 真实保存函数、HTTP 启动函数、任务工作线程及 pipeline.run_from_record 串联。平台登录、类目导航和上传服务器由隔离夹具模拟，名称/图片/价格/库存/详情/模板回读在独立本地 Chromium 中执行。
3. 明确区分任务执行成功、部分回读通过、整页必填验证完成和实际发布成功。只覆盖部分区域时，前端不得显示完整填写成功。
4. 正常流程、版本过期、实际必填缺值、取消及失败有独立反例；没有选择商品之外的媒体或真实店铺写入。
5. 类型检查、相关回归、真实 Sidecar 构建、归档和本地运行版本核对通过。

第一阶段结果只能描述软件实现和模拟环境行为，不能称为淘宝实机跑通。候选控件保持 candidate，不因模拟通过自动转为 verified。

## 第二阶段：真实店铺提交前实测

在获得直接提供的去敏结构或工具策略允许的页面访问后，确认自定义规格、SKU 图片、详情编辑器及整页必填控件，逐项调整适配并记录真实页面证据。最终完整填写当前商品并停在提交前，不保存草稿或提交。

当前工具对淘宝工作台的访问拒绝仍有效，换浏览器、插件、CDP 或内部接口不能解除该限制。密码、Cookie、验证码不是本阶段的输入。

## 本轮已确认的根因

- 只有可见属性的必填回读，前端仍可能显示完整填写。已增加独立 form_verification 摘要，整页覆盖缺失或范围不明时保持 partial/not_verified；任务成功不能代替完整验证。
- 主前端没有单独收集淘宝运费模板，而原处理器在空值时直接失败。桌面 custom 模式不再复用旧记录中未绑定平台的运费模板；仅允许核验并使用当前账户页面真实已选项，未选时明确失败，不选择“第一项”或猜默认值。最终回读仍比较该实际模板。

具体验证和构建结果在本轮证据日志中记录。原完整目标尚未完成。

- 本地真实保存/HTTP启动/工作线程/流水线/DOM串联4场景通过；正常场景执行10个提交前阶段，并保持`form_verification=partial`。
