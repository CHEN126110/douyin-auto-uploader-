# 32 · 图片空间去重复用

上传之前先问一句：**这张本地图，图片空间里是不是已经有了？** 本轮把这个问题做成一个可离线逐条断言的
判定层：`taobao-publish/taobao_publish/cloud_index.py`。它不联网、不碰 DOM、不读写磁盘、不引第三方依赖；
云端清单由既有 DOM 路线取（`find_product_images` / `read_directory_files`），本地清单由
`ProductMediaManifest` 给出，本层只做**精确对账**：不补默认值、不猜匹配、不自动重传。

## 这一层产出什么

入口一个：`index_cloud_media(manifest, listing, *, history=())` → `CloudIndexDecision`（`@dataclass(frozen=True, slots=True)`）。

| 字段 | 含义 | 关键字段 |
|---|---|---|
| `reuse` | 可以直接复用云端回执的本地图 | `relative_path`、云端 `name`、`url`、`folder_path`、`sha256`、`page`、`content_verified` |
| `upload` | 云端确实没有、必须上传 | `relative_path`、`name`、`sha256`、`size`、**预期**云端 `folder_path`、中文 `reason` |
| `ambiguous` | 可判但不唯一 | `code`、中文 `reason`、`candidates` |
| `blocked` | 判定根本无法进行 | `code`、中文 `reason`；非空时其余三个列表**必为空** |

`blocked` 非空即整体不判（`decision.is_blocked`、`decision.blocked_reasons`）。
`missing` 是 `upload` 的别名（云端"没有"= 必须上传）。歧义码 `code` 取值：
`url_missing_or_insecure`、`same_name_different_url`、`same_name_multiple_copies`、`directory_mismatch`、
`content_changed`、`content_history_conflict`、`cloud_content_mismatch`；阻塞码：
`cloud_listing_incomplete`、`cloud_root_unrecognized`、`cloud_root_mismatch`、`cloud_entry_unreadable`、
`cloud_entry_without_name`、`cloud_entry_directory_unrecognized`、`cloud_entry_page_invalid`、
`cloud_entry_digest_invalid`。

### 输入形状

- `manifest`：`ProductMediaManifest`，或任何有 `folder_name` + `images` 的对象；`images` 每项允许
  `SourceImage`、`(相对路径, sha256, size)` 三元组、或同键 mapping。相对路径必须是规范 POSIX 形式
  （`主图/800/x.jpg`）：绝对路径、反斜杠、`a//b`、`a/./b`、`a/../b` 直接 `ValueError`，不静默改写。
- `listing`：`CloudListing(folder_name, files, complete)`；`files` 用 `find_product_images` 的 `receipts`
  或 `read_directory_files` 的 `files` 那种 mapping（`name`、`url`、`folder_path`，可选 `page`/`page_number`、
  `sha256`）。清单必须已限定在该商品子树内。
- `history`：可选，上一次的 `UploadedImageReceipt` 序列（或含 `relative_path`/`sha256` 的 mapping）。

## 判定规则

- **R1 精确匹配三条同时成立才算候选复用**：云端文件名 == 本地文件名（逐字符，不做大小写折叠、前后缀或
  "名字像"的匹配）；云端目录归属 == 本地预期目录（逐段相等）；云端 URL 是 https、有主机名、不带用户名密码。
- **R2 目录归属以商品根目录名为锚点**：从锚点开始的整段（含根目录名）才是归属，锚点之前（如「全部图片」
  这类图库容器）不参与判定。锚点出现 0 次或多次 → 目录不可识别，整体 `blocked`；不做前后缀兜底，也不
  静默丢弃别的商品条目。
- **R3 预期目录** = `(folder_name, *PurePosixPath(relative_path).parent.parts)`；`upload` 给的也是这个。
- **R4 URL 缺失 / 非文本 / 非 https / 带凭据** → `ambiguous`，不挑另一份看着正常的。
- **R5 同名但云端有两个不同 URL 值** → `ambiguous`（与 `find_product_images` 对"同名但图片地址不同"直接
  报错的既有策略一致），不自动挑第一个。
- **R6 同名同目录出现多份** → `ambiguous`，不挑第一份。
- **R7 同名但目录归属不符** → `ambiguous`，理由里同时给出云端目录与预期目录。
- **R8 本地内容变了（sha256 与历史回执不同）而云端同名** → `ambiguous`，**绝不静默复用**（理由见下节）。
- **R9 清单不完整**（`complete` 不为 `True`，含分页未读完、子树未展开、完整性未知）→ 整体 `blocked`，
  `reuse` / `upload` / `ambiguous` 全为空：不完整的清单既证明不了"云端已有"，也证明不了"必须上传"。
- **R10 云端为空且清单完整** → 全部 `upload`，这是合法状态，不是错误。
- **R11 结构性缺陷**（条目不可读、缺文件名、缺目录、条目 sha256/页码非法、云端根目录缺失或与本地不一致）
  → `blocked`，且不做部分判定。

## 为什么"内容变了但云端同名"不放进 upload

`ambiguous` 而不是 `upload`，理由是可证明性：云端导出清单只有名字、地址、目录，**读不到云端对象的真实
内容摘要**；而同名文件重新上传到平台上究竟是**覆盖**还是**改名保留**，本子项目没有实证（`unknown`）。
两条路都无法证明时把决定权交回调用方（可选：核对历史回执、人工确认），符合本子项目"宁可拒绝执行，也不
悄悄产出错误结果"的红线。只有摘要能证明一致时才复用，并在回执里标 `content_verified=True`：云端条目自带
`sha256` 且与本地一致，或历史回执同 sha；两者都在时**以云端条目自带摘要为准**（它描述云端对象当下的内容）。

## 证据等级

- **`verified`（离线）**：上述规则的实现与逐条断言在 `taobao-publisher/tests/test_cloud_index.py`，共 54 个
  用例（含参数化）：精确复用、商品根目录图片、云端为空、`complete` 不为 `True`、根目录不一致/缺失、其它商品
  条目、缺目录、坏 entry、URL 缺失/非 https/带凭据、同名不同地址、同名同目录多份、同名异目录、同地址异目录
  仍按精确目录命中、内容变化、历史回执同 sha、历史回执冲突、云端摘要不一致/一致、云端摘要优先于陈旧历史、
  近似名不匹配、混合清单不重不漏且保序、三元组/mapping 本地形状、列表形状的云端清单、非法本地路径与摘要、
  `CloudListing` 类型校验、纯标准库导入体检。命令：
  `python -m pytest taobao-publisher/tests/test_cloud_index.py -q` → `54 passed`。
- **`verified`（结构）**：`cloud_index.py` 只导入纯标准库（`dataclasses`、`pathlib.PurePosixPath`、`urllib.parse`、
  `collections.abc`、`typing`），无 `socket` / `requests` / `subprocess` / `urllib.request` / DOM 求值 / 文件读写，
  由上面最后一个用例把这条钉住。
- **未验证（真实平台）**：本层没有对真实淘宝图片空间跑过。以下行为在本轮**不是** `verified`：
  云端同名文件的内容一致性（清单不含摘要）、同名重传是覆盖还是改名（`unknown`）、跨会话图片 URL 是否稳定
  （因此 `history` 只比对 sha256，不假设 URL 稳定）、图库容器层与目录层级的实际形态（由 DOM 路线决定，
  本层只按锚点切分）。本层也**没有**接入 `form_adapters` / `stages`：`reuse` 目前没有生产调用方。

## 接入时要注意的两点

- `find_product_images` 返回的 `receipts` 是 **dict**，同名多份会被压掉；要判定"同名多份"必须用逐目录
  `read_directory_files` 的 `files` 列表拼接后传进来。
- `reuse[].folder_path` 是**云端完整路径**（可能含「全部图片」容器层），不能直接当
  `UploadedImageReceipt.folder` 用；后者按 `PreparedProductMedia.validate` 要求 `(folder_name, *相对路径父目录)`。

## 验证方式与边界

本层测试不依赖 `tmp_path`、浏览器、网络或真实店铺，因此在受限环境下也能照常跑（本机沙箱里
`os.mkdir(..., 0o700)` 目录不可用，正是 `tmp_path` 类测试在这一轮全量运行中报错的原因，与本层无关）。
真实平台行为要在接入后按 `docs/05-证据日志.md` 的方式单独取证升级，不能据本页宣称"真实去重已跑通"。
