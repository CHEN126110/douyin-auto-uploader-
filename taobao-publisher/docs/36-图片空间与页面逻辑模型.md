### 1.3 为什么两棵树必须分开看

1. **根表示不同**，同一个商品目录的完整路径在两页上不是同一个数组：`directory_folder_id(['ID-1074582642352']) → 1114918855143810805` ✅，而 `directory_folder_id(['全部图片','ID-1074582642352']) → None` ❌（E-291 原文）。所以任何"写死 `全部图片 + [商品名]`"的写法在素材中心页**必然失败**。
2. **可信度不同**：素材中心那棵树对"子目录是否存在"的回答**不可采信**（E-293）。若拿"读不到"当"不存在"去建目录，会造出**重复目录**——这正是接入自动建目录时引入的新风险。
3. **职责不同**：选图器是**选择**界面（只读 + 点卡片），素材中心是**管理**界面（唯一能建目录）。因此"读目录"主要发生在选图器，"建目录"只能发生在素材中心，两者之间必须有一次跨标签往返与有界等待。

> 现行代码已把这组差异收敛成显式的 `page` 参数：`PAGE_PICKER='选图器'` / `PAGE_MATERIAL_CENTER='素材中心'`（`media_library.py:15-16`），
> 由 `ensure_product_root(..., page=)`、`resolve_role_folder(..., page=)`、`directory_folder_id(..., page=)`、`open_directory(..., page=)`、
> `open_root_directory(..., page=)`、`product_root_path(..., page=)`、`read_directory_files(..., page=)` 逐层传递（`media_library.py:209/273/350/544/642/715/880`）。
> 等级：**verified**（代码）。

## 12. 变更规则（怎么加一条 reason）

1. **判据点唯一且不吞错**：新 reason 必须来自一处明确的判据（表达式返回 / 包装层判决），
   不允许"先 try 一下不行就换一个 reason"，也不允许用兜底掩盖（项目红线）。
2. **证据等级写进文档**：新结论必须在本文件里带 `verified/candidate/unknown/rejected` 与来源（代码 / 真机只读探针 / 推断）。
3. **reason 登记进封闭词表**：加进 `media_library.REASON_ACTIONS`（`media_library.py:45-68`），并给出**一步动作**；
   映射不到就是 `NO_USER_ACTION`（漏登记会在文案里显形，这本身是设计）。
4. **动作进白名单且只给一步**（动词开头、用户在当前界面立刻能做）。
5. **测试必须断言六项**：阶段 / 分支 / 页面 / 目标 / 判据原码 / 下一步——照
   `tests/test_media_route_folder_wiring.py:438-443` 的写法。
6. **不改文案以外的行为**：改措辞不得顺手改判据、等待时长或调用顺序；要改就单独一轮并更新本文。
7. **禁止兜底、吞错、重试、新增层**。
8. **要删代码就删整段**，并在原处留一句说明为何删除；**禁止删除或移动代码文件**。
9. 改完在**仓库根**跑 `python -m pytest taobao-publisher/tests -q`，并与 §10.1 的基线对照（当前基线：19F/1599P/7S/352 subtests）。
