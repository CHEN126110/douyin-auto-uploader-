# 完整填写回执与前端结果判断

2026-10-04，继续按原完整上传目标审查类目之后的链路。上一轮默认品牌及素材身份修复已经部署，本轮针对“全部必填已完成”的结果真实性，不改变共同右侧表单、上传入口和账户绑定方式。

## 已复现的缺陷

1. `whole_form_coverage_confirmed` 允许 `required=[]`、`checked=[]`、`checkedCount=0` 的空回执作为整页完整证据。
2. 必填清单有两项、`rowCount=1` 的矛盾回执也被判为完整。
3. 共同前端仅核验完整标记和覆盖范围，没有核验具体必填清单、可读能力、回读值及数量。新增反例在修复前实际得到 `success` 提示，断言失败。
4. 淘宝旧式 `status=success` 可落入通用成功分支；提交前填写的成功文案可直接继承后端“发布成功”文字。

前三项有纯函数及真实 SFC/store/API 隔离执行的反例。后两项也在修复后的真实前端执行中验证。以上都是本地软件证据，没有读取或操作真实商家页面。

## 当前判断规则

后端完整覆盖回执必须保留明确的整页范围、已读取行数、非空必填清单，以及每项唯一、支持读取、有值的对应回读。必填项数量不能超过已读取行数，回读项集合及数量必须对应。空清单和矛盾清单拒绝成为完整证据。

共同前端通过 `utils/taobaoFormVerification.ts` 验证同一组具体回执，额外要求任务来源是淘宝、终态为 `succeeded`、非校对模式、停在提交前、明确未确认发布，并且最终回读成功。旧式淘宝 `success` 不触发完整填写提示，仍向用户说明没有完整证据。

任务返回错误平台或缺少平台来源时，既有轮询边界会保留任务和编辑锁，不应用该结果；连续错误后暂停读取，并允许重新读取当前任务。这个账户隔离行为没有被结果判断改动取代。

完整填写的正向提示固定说明“本次填写与回读已完成，已停在提交前”。不把后端任意完成文案当成商品上架事实。抖音的终态分支保持原有平台处理。
