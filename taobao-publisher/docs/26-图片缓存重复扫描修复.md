# 26 · 图片缓存重复扫描修复

2026-10-05，续接 E-193 的一次上传版本，范围是已知图片查找路径的效率与准确性，不改变完整商品填写和提交前停止的验收标准。

## 根因与复现

`enter_product_group(..., missing_ok=True)` 原来在没有匹配商品父目录或没有可识别目录树时，返回当前目录路径。`prepare_media` 将这个返回值当作用途子目录，分别为主图、SKU、详情扫描同一图库；未找到的图片又合并扫描一次根图库。

新增 `test_media_cache_scan_efficiency.py` 在修改前实际产生两个失败：平铺图库、只有其它商品目录的图库均出现 `[2,2,4,4]` 四次查询，而所需仅是上传前后 `[4,4]` 两次查询。已有本商品用途目录的缓存路径同时验证通过，说明问题在“没有专属目录”的分支。

这只能证明本地代码中的冗余查询，不证明真实淘宝图片阶段所有等待都由这个原因引起。

## 修复

- 可选缓存导航在未找到对应用途目录时返回 `None`，交给统一的根图库查询；保留其它调用方式的既有语义。
- 只有实际进入了商品用途目录，才显示“进入主图/SKU/详情目录”的进度。
- 已有本商品用途目录仍优先查询；若这些目录已确认全部素材，就不再扫描无关的根图库。
- 平铺或只有其它商品目录时，各用途合并为一次根图库查询；全部已有缓存时零上传，有缺图时仍只上传一批。
- 目录歧义、读取错误、文件名歧义及未完成图库遍历的处理没有放宽。没有把查找失败当成缺图许可。
