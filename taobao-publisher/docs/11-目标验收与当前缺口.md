## 本轮已修复的根因

原预检、填标题处理器和结果摘要都用 Python len，31个汉字会被当成31字符放行；原资料准备路径却已经提示汉字计2。同一资料在不同路径得到不同结论。现在共用 text_rules.count_title_units，前端计数也使用同一范围，中文/ASCII边界在前后端一致。标题上限仍从 contracts/rules.json 读取，在打开浏览器前返回明确400；前端没有新建另一份硬编码上限。非文本字段不再静默丢弃。

归档页面直接证明本次样本的30汉字/60字符提示；[淘宝开放平台公开接口文档](https://developer.alibaba.com/docs/api.htm?apiId=20)也记录标题字节上限，但不能将该接口的字节说明机械等同于所有工作台类目的实时 Unicode 计数。其它字符仍保留未验证说明，不宣称全平台规则已核实。

原 SKU_1x1 扫描只有说明文字，没有保存发现结果；现在 AssetDiscovery.square_images 传递到 LocalProduct.square_images。发布意图的 images.sku 使用本次请求 SKU 行的实际图片路径，去重但保留顺序，显式空列表仍被尊重；不按同名自动替换图片。目录扫描新增当前商品边界、符号链接与 Windows 重解析点检查，不会跟随链接上传其它目录的素材，原图不改动。
