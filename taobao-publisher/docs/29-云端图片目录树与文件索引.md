# 29 · 云端图片目录树与文件索引

用户先提出本地商品文件夹与图片空间对应关系，随后明确重点是：上传之后，自动化应知道淘宝图片空间内的文件树，准确进入目录选图，本地关联不是前提。本轮按这一优先级实现。

## 发布链路中的能力

- `product_directory_tree` 从页面当前目录树定位唯一商品父目录，展开本商品的懒加载子树。记录平台实际路径，不把目录限定为“主图 / SKU / 详情页”三种名称，也不展开其它商品。
- `read_directory_files` 进入指定目录，读取图片的完整文件名、完整 URL、页码。读取结束再次核对所选目录。只有当前支持的目录结构、文件名归属、图片身份和分页控件能确认时，才返回可用清单。
- `find_product_images` 为上传前复用、上传后定位共用的云端目录索引。父目录、子目录和更深层目录均参与查找，同名且 URL 不同的素材不能自动选第一张。
- 已支持 Next 分页结构的目录会从第一页遍历，选图时回到回执中的页码，再按完整文件名与完整 URL 核对。控件歧义、按钮可能提交表单、分页未稳定或超过遍历上限会明确报错；不把半页或截断清单当作全目录。
- 主图和 SKU 沿实际目录及页码选图，详情复用已确认 URL。目录接口本身无需本地商品文件；真实上架仍须有商品的主图顺序和 SKU 对应关系，不能仅按图库展示顺序猜选。

证据等级：上述生产实现与隔离页面行为为 `verified`；当前淘宝网站 DOM 是否覆盖这些候选结构仍为 `candidate`，没有通过其它工具读取受限后台。

## 辅助查看入口与回执

商品列表右键“商品图片”（键盘 Shift+F10）按需打开目录窗口。逐层查看本地目录、子目录、图片预览和文件信息；不改变右侧发布表单，也不刷新或覆盖未保存商品资料。

淘宝填写任务把“队列完成但尚未定位”与“已找到图片、最近确认目录”分开记录。失败和取消的流水线也返回已经发生的素材事实。记录绑定本地账户、商品编号和商品根目录；本地图片改动后标记内容变化。只存相对路径、摘要、上传名、目录与时间，不持久化平台 URL、登录资料或请求头。

这些记录是历史事实，不是即时云端状态。旧任务没有记录时显示无记录，不能据此认定未上传。下一次自动化仍读取当前页面确认。读取本地目录时禁止越界路径、符号链接和目录联接；损坏索引明确报错，不冒充空记录。

## 验证与边界

`test_cloud_media_tree.py` 使用新建的隔离浏览器，覆盖不依赖本地文件的云端目录读取、多级目录、异步展开、其它商品隔离、同名冲突、失败上传事实保留、完整分页后回到指定页选图，以及深层已有图片不重复上传。

`test_product_media.py` 在临时目录与 Flask test_client 中验证目录内容、自然排序、路径边界、按账户隔离、文件改动识别、原图不改写、损坏记录与 HTTP 接口。`frontend_media_flow.cjs` 执行真实 Pinia/API 源码，覆盖请求乱序、关闭时取消回写、账户切换、真实错误信息及中文路径编码。

完整测试、构建和部署结果归档于 `outputs/desktop_cloud_media_validation.json`、`desktop_cloud_media_build.json`、`desktop_cloud_media_runtime.json`。不以这些本地证据宣称当前真实淘宝已经跑通；完整必填回读及真实上传后的目录适配仍需当前页面确认。范围继续停在提交前，不保存草稿、不发布。
