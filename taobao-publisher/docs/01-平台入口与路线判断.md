# 01 · 平台入口与路线判断

> 结论等级：【**实证**】。来源见文末。
> 本文回答一个问题：**淘宝发布到底能不能走官方 API？** 答案是不能，因此后续全部设计
> 都建立在「网页工作台 + mtop / DOM」之上。

## 1. 结论

普通**淘宝集市卖家**没有可自研对接的官方发品 API。三条路都堵着：

| 路线 | 状态 | 依据 |
|---|---|---|
| 老 TOP 接口（`taobao.item.add` / `taobao.item.update` / `taobao.itemprops.get` …） | **已下线** | 平台 2022-07-29 公告：自 2022-08-31 起逐步下线原有商品发布、商品编辑等接口 |
| 新接口（`alibaba.item.publish.submit` / `alibaba.item.publish.schema.get` …） | **自研身份不开放给集市卖家** | 官方权限页原文：「开发者账号要求**必须是天猫商家**」，且必须入驻聚石塔、只能服务自己店铺 |
| 第三方 ISV 路线 | **门槛高且合规成本重** | 需企业实名 → 创建应用 → 提交方案+资质 → 小二审核 5–10 个工作日 → 上线服务市场售卖 |

**因此本子项目不做 API 路线**，只在网页工作台上做文章。这不是取巧，是被平台规则
逼出来的唯一可行解。

## 2. 网页发布工作台

### 入口

| 入口 | URL | 说明 |
|---|---|---|
| 淘宝发布工作台 | `https://item.upload.taobao.com/sell/ai/category.htm` | 类目选择页（「以图发品 / 搜索发品」）；站点路径为【商品】-【发布商品】 |
| 天猫发布页 | `https://item.upload.tmall.com/router/publish.htm` | 天猫独立域名 |

### 类目选择的两条路径

1. **搜索发品**：输入产品名 / 类目关键词 / 条码 → 系统推荐类目。
2. **以图发品**：上传商品图 / 模特图 → 自动识别推荐类目。

官方页面同时明确提醒「避免类目错放被处罚」——这条对自动化是个警告：**类目不能猜**，
必须让人确认，或至少要有可核验的映射依据。

### 阶段划分

```
类目选择 → 标题/属性 → 销售属性与 SKU → 主图/详情（图片空间）→ 价格库存 → 物流（运费模板）→ 提交
```

其中「部分类目提交后进入人工审核」——这意味着**提交成功 ≠ 商品已上架**，
流水线的成功判定不能只看接口返回值。

## 3. 类目属性体系（设计的核心难点）

淘宝的类目属性是「**类目 + 属性 ID + 属性值 ID**」三元组，且**每个类目各不相同**。

老 TOP 文档给出的字段语义，是理解新版 schema 的钥匙（注意：这是**老接口**语义，
不能证明当前网页工作台仍用同名参数，故在契约里标为 `candidate`）：

| 语义 | 老 TOP 表达 |
|---|---|
| 枚举属性 | `props` = `pid:vid`（多个用 `;` 分隔） |
| 自定义属性 | `input_pids` + `input_str` |
| 自定义销售属性 | `input_custom_cpv` |
| SKU 组合 | 销售属性值的**笛卡尔积**拼接成 `sku_properties` |
| SKU 价格 / 库存 / 编码 | `sku_prices` / `sku_quantities` / `sku_outer_ids` |
| 运费模板 | `postage_id` |
| 主图 | `pic_path` |

**官方明确要求属性值动态映射**，原文要点：针对每一个商家实现动态映射能力，
改变以前写死参数的方式，并每日拉取类目规则做差异检测。

→ 落到本子项目的设计：`contracts/field_mapping.json` 里属性字段的证据等级是
`candidate`，且 `item.props` 的 `blocker_hint` 明确写了「禁止硬编码 pid/vid」。
`PropEntry` 里 `prop_id` / `value_id` 允许为空，为空时载荷里标
`ids_resolved: false`，由 `fill_props` 阶段或人工补齐 —— **不生成假的 ID**。

## 4. 图片

| 项 | 要求 |
|---|---|
| 主图数量 | 最多 5 张，**第 5 张为白底图** |
| 比例 / 尺寸 | 1:1；最低 480px；经典 800×800；2026 新规建议宽度 1440px |
| 体积 | 经典 ≤3MB；2026 新规称放宽到 20MB 并上线质量检测 |
| 白底图 | 纯白 RGB(255,255,255)、无文字 / Logo / 水印 / 阴影 / 模特，主体 ≥300×300 |
| 盗链 | 外链图会被判「引用 Picture 存在盗链」，**详情图一张出问题整单过不了审核** |

→ 落到本子项目：`contracts/rules.json` 收录了数量 / 尺寸 / 比例 / 体积四条硬约束。
其中体积一项目前只告警不阻塞，因为「3MB 经典限制」与「2026 放宽到 20MB」两说冲突，
契约里如实记录了这个冲突，等实测确认后再定。

→ **盗链这条决定了图片必须先入图片空间**（或放到可公开外链的服务器）。
本地 `src/whitebg/` 产出的白底图正好可以喂给第 5 张主图位。

## 5. 风控与令牌

| 项 | 值 |
|---|---|
| 网关 | `h5api.m.taobao.com`（H5） |
| `_m_h5_tk` 格式 | `明文token_expireTime`，token 取 `_` 前 32 字符 |
| 签名 | `md5(token & t & appKey & data)`，`t` 为毫秒时间戳 |
| H5 appKey | `12574478`（仓库读路径实测使用中） |
| token 有效期 | 约 60 分钟（cookie 本身 7 天） |
| token 过期 | 返回 `FAIL_SYS_TOKEN_EXOIRED` 并 Set-Cookie 新 token（可自愈一次） |
| 签名错误 | `FAIL_SYS_ILLEGAL_ACCESS` / `Sign Error` |
| 非 JSON 响应 | 多为 baxia / x5sec 风控页 |

→ 落到本子项目：`taobao_publish/mtop.py` 把签名做成**纯函数**并有单元测试
（含硬编码测试向量）。它**只算签名、不发请求**；请求发送交给浏览器内 `fetch`
或 CDP，这样 TLS 指纹与 cookie 都由真实浏览器提供。

## 6. 已知坑（提交前预检要点）

| 坑 | 后果 |
|---|---|
| 类目错放 | 被平台处罚（官方明确提醒） |
| 一口价不在 SKU 价格区间内 | 发布失败 |
| 关键属性选「其他」但没补 `input_pids` + `input_str` | 发布失败 |
| 管控类目（食品 / 酒类 / 书籍 / 保健品 / 农药 / 医疗等）无资质 | 发布失败 |
| 详情图存在盗链 | 整单审核不过 |

→ 前三条已分别落到 `preflight`（价格）、`fill_props`（属性）、`validate_skus`。
管控类目资质**不做程序预判**（没有可信清单），在 `contracts/rules.json` 的
`unknown_rules` 里显式记为未知，由人工在类目选择阶段确认。

## 7. 仍未知的部分（不臆造）

- API 调用频率 / QPS 官方数字。
- 发布接口官方错误码**全集**。
- 标题违禁词官方词表（`rule.taobao.com` 正文未取到）。
- 重复铺货判定细则原文。
- **淘宝集市卖家能否申请自研身份**：官方页面只见到「天猫商家自研」入口。

这些全部记在 `contracts/rules.json` 的 `unknown_rules` 与
[`06-阻塞项.md`](06-阻塞项.md) 里，**没有一条被写成默认值塞进代码**。
