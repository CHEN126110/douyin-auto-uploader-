# 31 · 图片空间协议上传端点取证

本轮把「淘宝图片空间（发布页素材中心）到底用什么接口上传图片」这一 `unknown` 取证到了**端点级**：
`POST https://stream-upload.taobao.com/api/upload.api`（multipart）+ 一条 `mtop.taobao.mediacenter.pc.image.upload.*`
的**分片直传**编排链 + 一整套 `mtop.taobao.picturecenter.console.*` 图片空间读写接口。

取证方式**全程只读**：不登录、不带 cookie、不发任何写请求，只 GET 公开前端资源并做静态分析；
另外用 CDP 对发布页做了一次被动网络观察，用来确认当前登录态。

> **证据边界（必须先读）**
> 下面标 `verified` 的条目，含义是「**官方前端 bundle 里确实这样调用**，且脚本可复跑、产物已归档」。
> 它**不**等于「本仓库已在登录态下调用成功」：运行时返回值、鉴权方式、字段取值仍是 `unknown`，
> 原因是 9334 调试实例**没有登录态**（见 §7）。按 `AGENTS.md` §2，这类缺口只能记为 blocker，
> 不允许用默认值填充。


上传面板 `PicUpload`（`js/PicUpload.5b071f5e.chunk.js`）的普通分支用 Plupload 上传器，把 URL 与
`multipart_params` 一次性配置进去：

```js
o = { url: "", multipart_params: {} };
l = window.uabModule && window.uabModule.getUA({...});          // UA 令牌
o.url = stringifyUrl({ url: SP.upload, query: pickBy({
      appkey: "tu",
      folderId: i.getNative().parentId || "0",                  // 图片空间目录 ID，根目录为 "0"
      watermark: cfg?.watermark || false,
      picCompress: !cfg.originSize,
      _input_charset: "utf-8" }, v => v !== undefined) });
l && (o.multipart_params = { ua: l });
n.setOption(o);                                                  // 交给 Plupload 发 multipart
```

`folderId` 就是图片空间目录（`pictureCategoryId`）；`sucai-batch-upload@0.0.17` 里同名常量与同一组参数再次出现，
说明这是图片空间**统一的图片上传网关**，选择器与批量上传共用。

**注意：`upload.api` 有两条互不相同的 body 构造，不能只写一张字段表。**

| 路径 | body 字段 | 说明 |
|---|---|---|
| 本地上传（Plupload，`jumpXhr=false`） | `ua`（仅此一个由前端显式配置） | `ua = window.uabModule.getUA({Token:…})`，仅当 `window.uabModule` 存在时 `multipart_params={ua:l}`；**没有** `water`、**没有** `_tb_token_`；文件字段名 bundle 里没有（无 `file_data_name`/`fileVal` 配置）→ 由 Plupload 默认决定，未取证 |
| 裁剪 / 替换（`sucaiTu` chunk、`sucai-tu-selector` 裁剪分支） | `water="false"`、`name=<名>.<ext>`、`_tb_token_=<取自 cookie>`、`file=<blob, filename>` | `water` 在 **body**、`watermark` 在 **query**，两者不同；cookie 值经 js-cookie 读取 |
| AI 生成图（`appkey=qnaigc`） | `name=<前20字符>.jpeg`、`file=<blob>` | 该路径读了 `_tb_token_` 但返回值被丢弃，body 里没有它 |

两条 Plupload/FormData 路径的 query 都**只有业务参数**，没有任何鉴权类 query 参数（无 `_tb_token_`、`t`、`sign`、`token`）；
`folderId` 在 Plupload 路径恒有（`parentId || "0"`），在显式 FormData 路径是 `t?.pictureCategoryId`，可能为 `undefined`
（axios 会丢弃 undefined，即**存在不带 `folderId` 的调用形态**）。

**仍未取证**：Plupload 的 multipart 字段名（默认 `file`，裁剪分支显式用 `file`，但普通分支的字段名未在代码里写死，
需要登录态下抓一次真实请求才能升为 `verified`）；`ua` 缺失是否被拒。

### 3.1 两条 body 构造（同一上传网关，字段不一样）

把 6 个微模块里所有调用 `SP.upload` 的地方对齐后可以确认：**同一个 `upload.api` 有两条互不相同的 body 构造**。

**(A) 显式 `FormData`（裁剪 / 替换 / AI 上传，共 3 处）**

```js
t = new FormData();
t.append("water", "false");
t.append("name", "<文件名>.<ext>");
t.append("_tb_token_", cookie.get("_tb_token_"));   // 从 cookie 读，放进 body
t.append("file", blob, "<文件名>.<ext>");            // 文件字段名 = file（原文写死）
// query: _input_charset=utf-8, appkey=tu, autoCompress=false, folderId=<pictureCategoryId>,
//        picCompress=true, resizeWidth=false, watermark=false, width=0, hideUserId=<bool>
```

**(B) Plupload（普通本地上传）**

```js
o.url = stringifyUrl({ url: SP.upload, query: pickBy({
      appkey: "tu", folderId: parentId || "0", watermark: cfg?.watermark || false,
      picCompress: !cfg.originSize, _input_charset: "utf-8" }) });
l = window.uabModule && window.uabModule.getUA({ Token: <运行时令牌> });
l && (o.multipart_params = { ua: l });     // body 里**只显式放了 ua**
```

两条的差别（都是 bundle 原文，`verified`）：

| 项 | (A) 显式 FormData | (B) Plupload |
|---|---|---|
| body 字段 | `water`、`name`、`_tb_token_`、`file` | 仅显式 `ua`；文件字段由 Plupload 内部默认决定（未写死，**unknown**） |
| `_tb_token_` | 有（从 cookie 读） | 无 |
| `ua` | 无 | 有（`uabModule.getUA()` 的返回值，无法离线复现） |
| `folderId` | `pictureCategoryId`，**无兜底**（可能不下发） | `parentId \|\| "0"`，总是带 |
| query 里的鉴权参数 | **没有任何** `sign`/`t`/`token`；靠 cookie 会话 + body 的 `_tb_token_` | 同左；**是否带 cookie 在 bundle 里看不出来**（`unknown`） |

**本仓库的选择**：协议上传按 **(A)** 发（`taobao_publish/upload_api.py` 的
`build_request_body`，字段顺序 `water` → `name` → `_tb_token_` → `file`）——
理由是 (A) 的四个字段都有原文，(B) 的文件字段名在原文里根本查不到。
风险也写在那儿：**登录态下实测的第一件事**就是确认 (A) 是否被接受，
以及 (B) 是否真的带 cookie（若 (B) 才是主路径，字段表要跟着改）。


## 4. 上传路径 B：大文件分片直传（mtop 三步 + PUT）

```js
parts = await Promise.all(slices.map(PUT, "application/octet-stream"));  // 取 ETag / object.ETag 当分片 md5
```

## 9. 阻塞项（`unknown`，需要人工介入才能升 `verified`）

1. **需要扫码登录一次 9334 实例**（`.runtime/chrome-taobao-cdp`，登录态随 profile 持久化）。
   没有登录态就没有任何运行时证据：`upload.api` 的请求/响应、`folderId` 的真实取值、错误码映射都取不到。
2. `upload.api` 的**鉴权方式**已部分取证：query 里**没有**任何签名/令牌参数（`sign`/`t`/`token`/`_m_h5_tk` 全无命中），
   鉴权靠 cookie 会话；显式 `FormData` 那条路径另把 cookie 里的 `_tb_token_` 放进 body（§3.1）。
   **仍 `unknown`**：Plupload 路径是否 `withCredentials`，以及只带 cookie 不带 `_tb_token_` 会不会被拒。
3. `uploadUrlList`（分片直传）的 host 与签名形态未取证（需登录态真传一次；且按红线不得落签名 URL）。
4. Plupload 普通分支的 multipart 字段名未写死在代码里（默认 `file`，未实证）——
   本仓库因此改按显式 `FormData` 那条路径发，字段名与字段表见 §3.1。
