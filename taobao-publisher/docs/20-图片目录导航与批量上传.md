# 图片目录导航与批量上传

> **图片阶段再次修复（E-186/E-187）**：上传前后逐张重扫图库改成按用途整批查询；主图按位置身份补传，修复部分缓存时文件与名称错配；每张主图重新进入下一个空位的选择器。五主图+SKU/详情的隔离11阶段模型通过，真实工作台仍未验收。见 [整批查询与主图位置](23-整批图库查询与主图位置.md)。

2026-10-05，用户报告卡在“上传中：40% - 上传商品图片”，并说明图片空间需要先进入商品父目录，再进入主图、SKU、详情页子目录。当前工具未读取该淘宝页面；以下将源码问题、本地验证和平台待确认项分开记录。

## 查明的实现缺口

1. 原 `find_media_image` 只滚动当前图片列表，没有目录导航。父目录只显示子文件夹时，无法通过滚动找到子文件夹中的图片。
2. `_upload_staged_files_to_media` 在点“完成”前逐文件调用 `wait_for_media_images`；其 `build_has_media_image_expression` 又排除了上传队列。已知平台需要点击完成后图片才入库，因此每张可能空等120秒，然后才从队列成功状态恢复继续。
3. SKU和详情的 `prepare_media` 每发现一张缺图就单独调用上传函数，重复打开和完成上传面板。
4. 逐张发送所引用的 E-118 批量不可靠结论，早已在证据日志 AC 节被纠正：当时误将上传队列文字当作图库图片。它不能继续作为禁用原生批量入口的依据。

## 当前方案

| 方式 | 本地操作成本 | 当前判断 |
|---|---|---|
| 旧逐张发送与等待 | 每张等待图库；SKU/详情每张打开并完成一次面板 | 已替换；顺序存在无效等待 |
| 按用途批量文件上传 | 支持multiple时，一次送入该用途全部缺图；主图/SKU/详情最多各一批 | 当前采用，逐项检查队列成功；单文件原生入口仍逐个接收 |
| 一次导入整个商品文件夹 | 浏览器目录输入可一次接收父目录并保留相对路径 | 仅浏览器原生能力已验证；淘宝云端目录创建、同名合并及上传目标规则未验证，未设为默认自动策略 |

这里比较的是可证明的入口调用次数，不声称真实网络吞吐率已测得。普通文件批量上传仍逐项检查本批文件名对应的成功状态；部分缺失、错误或重复项不会被当成整批成功，也不会自动重传掩盖第一次结果。

上传顺序改为：**准备已校验的素材快照 → 一次送入支持多文件的输入框 → 等本批队列逐项成功 → 点击完成 → 在实际图片目录核对完整文件名/URL → 选择进商品图片位**。不再在完成前等待图库出现。

目录导航限定在素材iframe内可识别的ARIA/Next目录树：按商品父目录和用途子目录精确定位，重复父目录不选第一个，点击后回读选中路径。目标已渲染时直接进入，已在目标目录时不再点击祖先。主图和SKU图片回执保存实际目录路径，重新打开弹层后返回该路径再选图。两项目录选择器保持candidate，当前模型并不提升平台证据。

上传面板的“上传至”与图库选择可能不同。新上传图片只在完成后的实际选中目录、已确认的商品用途目录这两个明确位置核验；找到后记录实际路径。两个位置均没有完整身份卡片则报出原因，不再上传另一份，不盲扫其它商品目录。

进度沿用共同前端，显示“进入SKU目录”“上传详情页图片：N张，等待本批队列全部成功”“选择主图：i/N”等具体子步骤。

## 验证与边界

- `test_media_queue_batches.py`：包含真实隔离浏览器中的原生multiple输入、上传队列和完成按钮模型；一次输入接收3个文件，队列成功后只点一次完成，之后才出现图库内容。另覆盖缺图、拒绝、重复项和单文件入口。
- `test_media_directory_flow.py`：父目录无图、不同商品同名用途目录、重复商品目录、SKU/详情按目录批量处理，以及真实HTTP工作线程串联的11阶段模型。5张图按主图1张、SKU2张、详情2张分成3次上传调用，没有保存草稿或提交。
- `test_media_folder_capability.py`：新建独立 `file:` 浏览器，通过真实原生目录输入读取 `123/主图`、`123/SKU`、`123/详情页` 的相对路径；目录枚举是异步的，需要等待文件列表形成。

官方资料也将普通多文件输入与目录输入区分：[Playwright文件上传说明](https://playwright.dev/docs/input#upload-files)、[目录输入约束](https://playwright.dev/docs/api/class-page#page-set-input-files)。这些文档证明浏览器自动化能力，不证明淘宝目录导入的业务规则。

没有访问当前真实淘宝工作台，没有实际上传、保存草稿或上架。当前目录树适配仍需要实际页面匹配；中间文件夹卡片的双击交互尚未实现。整页必填覆盖仍沿用partial结果，不能把这次图库修复报成完整商品验收。
