# 共同上传数据交接

用户点击上传时，两平台都应消费当前商品编辑内容。当前抖音入口原先只传 record_id，工作线程随后从 SQLite 读取记录；淘宝入口则传当前表单快照。这导致右侧未点击“保存”的售价、规格名称和库存可能在两平台得到不同结果。

## 当前实现

共同入口先固定当前商品、店铺平台、profile、标题、类目、库存及逐 SKU 名称和售价，确认保存后再启动上传。单价输入作为临时填价/智能定价输入，上传只使用每行实际售价，不用它覆盖 SKU 价格。前端布局不新增控件，保存过程使用共同上传遮罩。

保存前后若所选商品或账户变化，拒绝启动本次任务。任务已经启动后仍追踪原 task_id，不因后续界面变化丢弃进度。保存回执必须确认当前商品 ID 和资料版本；启动端点再次核对该版本，防止保存与任务启动的间隙读取其他修改。指纹只涵盖发布会消费的商品字段，不包含登录信息，也不把分钟级更新时间当成版本。

保存接口先完整校验，再修改单条 ORM 记录。库存/类目拒绝错误类型或小数；SKU 来源、数量、重复行、售价及字段类型失败时不改任何字段。价格解析失败不会写成0。手工保存可保留用户明确输入的0元草稿价格；上传前保存要求正数且最多两位小数。原始 SKU 辅助字段和未提供的记录字段保留。运行任务所消费的记录暂不允许保存，批量任务覆盖全部记录。

新增 HTTP 字段：保存使用 for_publish、platform、account_profile，回执包含 record_revision；两平台启动可携带 expected_record_revision。旧入口不携带版本时保留原语义，桌面共同入口始终携带已确认版本。无效版本或资料变化在浏览器/工作线程启动前明确拒绝。

## 完整性报告

SKU图片、自定义规格和详情编辑的当前页面结构仍缺证据。回读阶段若收到 SKU 图片或详情素材、但对应处理器尚未接入，就明确返回 EVIDENCE_INSUFFICIENT，不能把“图片路径已进入模型”报告为“全部填写完成”。这项错误提示反映真实缺口，不是新增前端资料检查页面，也不代替后续实现。

用户仍需提供单层自定义规格切换后的输入/图片控件以及详情编辑器的结构，或在工具访问策略明确允许的环境中取证。已有归档仅证明模式单选按钮、属性块“添加图片”文字和必填“宝贝详情”行，无法证明具体写入目标。本轮没有换工具或内部接口读取淘宝页面。

## 验证

tests/test_product_save_snapshot.py 执行真实 Flask 函数与隔离 ORM，含真实内存 SQLite 的保存、重载、价格变化版本拒绝测试。frontend_publish_flow.cjs 执行实际 SFC、store和API源码，覆盖共同快照、保存失败、账户/商品变化、版本回执匹配和启动参数。

本轮定向回归240项通过，其中保存与SQLite数据交接44项；前端44组行为及vue-tsc/Vite构建通过。冻结代码和部署核对另存为 outputs/desktop_goal_data_handoff_build.json 与 outputs/desktop_goal_data_handoff_runtime.json。全套与最终部署结果以这些产物和证据日志为准，不能据离线通过宣称当前店铺上传已跑通。

本轮淘宝全套离线最终结果：1072 passed、7 skipped、318 subtests passed；保存/接口/账户/发布安全定向240 passed；真实前端44组行为通过。两个涉及本地运行环境或真实根数据库的用例继续明确排除。
