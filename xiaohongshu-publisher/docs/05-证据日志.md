  用 `document.elementFromPoint` 反查后确认——点击坐标 606,309 **确实命中**
  `upload-trigger__label` 里的「上传图片」文本，命中链为
  `span.d-text → div.upload-trigger__label → div.upload-trigger_container → div.upload-trigger
  → div.upload-list → div.material-space.base-images-init-uploader`，且在**上传区之内**
  （区框 x210 y197 w966 h200）。但点击后 0.3/1.0/2.5 秒三个时间点读到的状态**全部没变化**
  （`drawer_open=false`、`mask_count=0`、页面文案里没有「我的图片」「上传本地图片」）。

  自检给出关键线索：**`document.visibilityState === 'hidden'`**（而 `hasFocus=true`）。
  浏览器对**不可见页面**会节流渲染与事件处理 —— 这与「同一坐标有时生效、有时不生效」
  完全吻合（成功那次页面在可见标签页里）。用 Win32 `ShowWindow(SW_RESTORE)` +
  `SetForegroundWindow` 恢复窗口**不足以**改变它，说明是**标签页**层面的不可见。

  **硬规则（写进实现约定）**：对千帆页面的 UI 自动化必须在**可见标签页**里做——
  先 `Target.activateTarget` 把它激活（必要时直接在新建的前台标签页里操作），
  并在动作前断言 `document.visibilityState === 'visible'`，否则**不执行点击**
  （避免"点了没反应"被误判成"控件不存在"）。
  复现：`python xiaohongshu-publisher/tmp/probe-xhs-upload-hit.py 9336`。
