# 阶段计划

## P0：干净基线

目标：确保新研究区和旧研究区隔离。

完成标准：

- 本目录有独立文档和产物位置。
- 文件名使用 ASCII。
- 不修改正式流水线。

## P1：价格库存接口再实证

目标：重新确认价格库存相关字段如何进入真实请求体。

重点字段：

- `sku_detail[].price`
- `sku_detail[].stock`
- `sku_detail[].stock_info`
- `sku_detail[].spec_detail_ids`
- 运费模板、上下架、发货相关控制字段

完成标准：

- 有去敏后的真实请求体摘要。
- 能解释每个被修改字段的来源。
- 能判断哪些字段可以独立补丁，哪些字段依赖 SKU 结构。

## P2：离线补丁器

目标：先做离线 body 解析和差异输出，不向平台发送请求。

完成标准：

- 输入去敏样本和本地 SKU 目标值。
- 输出补丁后的 body 摘要。
- 输出字段差异和无法补丁的 blocker。

## P3：阶段性执行器评估

目标：判断价格库存能否替代 DOM 填写阶段。

进入条件：

- 离线补丁器稳定。
- 字段来源清晰。
- 有接口级校验方案。
- 不依赖保存草稿 replay 作为正式路径。

## 暂停方向

- 暂不做完整最终提交协议化。
- 暂不把编辑态 replay 当成落地主路径。
- 暂不继续假设 `saveMaterial` 或 `submitWhiteImg` 是必经链。
