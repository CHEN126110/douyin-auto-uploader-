# 协议化自动化流水线目标

创建日期：2026-05-05

## 核心目标

把当前依赖 DOM 点击、输入、等待的发布流程，逐步替换为可审计、可复跑、可校验的协议化自动化流水线。

最终目标不是“抓到一个提交接口就直接发品”，而是形成阶段化执行器：

1. 会话与页面上下文
2. 类目与 schema
3. 标题与基础属性
4. 主图与媒体资源
5. 规格轴与 SKU 结构
6. 价格库存与发货设置
7. 提交前校验
8. 保存草稿或正式发布

每个阶段必须有明确输入、接口、输出、校验和失败原因。

## 不接受的实现方式

- 不把 Cookie 固化到脚本里。
- 不绕过登录、验证码、风控或平台权限。
- 不用硬编码兜底掩盖字段缺失。
- 不把旧抓包样例直接当成所有类目的通用协议。
- 不在证据不足时把协议提交接入正式按钮。

## 第一轮接口发现目标

先找到并复核接口，不急着写正式执行器。

优先级：

1. 只读接口：类目、schema、运费、运行态选项。
2. 低风险写接口：图片上传、白底检测、AI 任务状态查询。
3. 核心 envelope：`addWithSchema` / `editWithSchema` 的请求体结构。
4. 阶段化切口：价格库存、SKU 结构、类目属性。

## 第一轮完成标准

- 生成接口矩阵。
- 每个接口标注读写风险。
- 每个接口标注可复跑探针。
- 每个接口标注证据状态：源码线索、只读实证、截停实证、服务端接受实证。
- 选定第一个可落地阶段执行器。
