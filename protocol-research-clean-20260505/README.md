# 抖店协议自动化干净研究区

创建日期：2026-05-05

本目录用于从零重新研究抖店发布页协议接口，避免干扰现有 `protocol-research`、`mcp-server` 和正式 DOM 上传流水线。

## 当前定位

这里不是正式上传实现目录，也不是旧研究目录的拷贝。

当前只做三件事：

1. 重新建立接口证据链。
2. 重新区分候选接口、已实证接口和不能落地的方向。
3. 为后续阶段性自动化执行器准备清晰输入、输出和校验规则。

## 目录结构

- `docs/`：研究计划、接口地图、证据日志、阻塞项。
- `captures/`：去敏后的抓包摘要。不得保存敏感原文。
- `schemas/`：只读 schema 摘要和字段矩阵。
- `scripts/`：本目录专用脚本。脚本默认只读或离线分析。
- `outputs/`：离线分析输出和阶段报告。
- `tmp/`：临时产物，可随时清理。

## 敏感信息处理

Cookie、token、签名 URL、手机号、店铺敏感信息不进入本目录。Cookie-Editor 导出只能通过 `scripts/sanitize_cookie_export.py` 生成去敏摘要。

## 第一阶段目标

优先只做一个高价值目标：价格库存阶段。

原因：

- 当前 DOM 价格库存填写依赖虚拟表格，天然慢且不稳定。
- 价格、库存、`stock_info` 的协议结构比完整发布提交更窄。
- 它适合作为第一个独立阶段执行器候选，不需要直接接管最终 `addWithSchema` 发布。

## 禁止事项

- 禁止直接接入正式上传按钮。
- 禁止把 dry-run 当成真实协议能力。
- 禁止猜测字段后硬提交。
- 禁止为了“跑通”而加兜底掩盖字段错误。
- 禁止保存未脱敏敏感数据。
