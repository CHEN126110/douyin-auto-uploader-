# 白底图语义抠图实验室

目标：把采集下来的袜子图做成**合规的白底图** —— 只有袜子、转正、1:1、主体居中。

平台自带的「一键抠图 → 白底图」用的是**显著性**分割，和袜子一起摆拍的鞋子、
毯子、礼盒都会被当成主体抠进来。这里加一层 CLIP 零样本**语义**判断，逐个连通域
问「这是不是袜子」，只留袜子。

实现已经搬到 [`src/whitebg/`](../../src/whitebg/)（单一真源），本目录只留实验脚本、
诊断脚本和结论。

---

## 结论速览

| 问题 | 实测结论 |
|------|----------|
| 用哪个 matte 模型 | **`birefnet-general`（MIT，927MB）**。能分开两只袜子之间那条地毯缝隙的只有它和 `bria-rmbg`；`u2netp` / `u2net` / `isnet-general-use` / `birefnet-general-lite` 全都把缝隙填成实前景。两者都能分开时选 birefnet：许可干净、抠得更净、22 张里成 19 张（bria 只成 13 张）|
| 鞋子怎么去掉 | 必须靠语义闸门。`birefnet-general` 和 `bria-rmbg` 给鞋子的都是**满 alpha**，靠阈值筛不掉 —— 模型越好这层越必需 |
| 语义闸门准不准 | 22 张实测：袜子域 sock 概率 0.79~0.99，鞋子域 0.18~0.41，中间有 0.37 的空档 |
| 转正怎么才不转错 | 单靠 PCA 会把「一排密排袜子」转倒 87.8°。需要三道护栏：场景不是群图 + 主体够细长 + 多主体方向一致。**只靠细长度不行，它是跟着 matte 模型变的** |
| 输出多大合适 | 画布 1440×1440。同一张图在 1200/1440/1600/1919 上对比，放大到 1.42 倍袜口织纹开始发软，1.60 倍明显糊 |
| 什么图做不出白底图 | 多色对照图、穿着图（脚/腿上）。这两类**如实拒绝**，不硬做 |

## 关键实证过程

### 1. 为什么必须做语义抠图

`isnet-general-use` 的结果里，鞋子是半透明的、毯子也带进来了 ——
和平台「一键抠图」的毛病一样（见用户提供的对照图：白底图右侧挂着一只黑鞋）。

出图：`out/01_matte_compare/`、`out/10_model_gap/*__models.jpg`

### 2. 两只袜子之间那条地毯

01_大花边 的两只袜子在花边和鞋头处互相搭住，中间露出一条约 80px 宽的米色毛圈地毯。

排查顺序（每一步都出了图，别再重复踩）：

1. **二次聚焦**（按主体外框裁原图再跑一遍 matte，提高有效分辨率）——
   缝隙仍然填实。isnet 的问题不只是分辨率，是它倾向于把凹陷填平。
   实现保留了（`matte.focused_alpha`），因为它确实让边缘更实。
2. **只补小洞不补大洞**（`matte.fill_small_holes`）—— 这个 bug 是我自己造的：
   原来用 `ndimage.binary_fill_holes` 无脑填洞，那条缝隙在拓扑上就是一个洞。
   改成按面积比例决定填不填之后，**这一条不再是原因**，但缝隙还在 ——
   因为模型本来就给了那里 150~250 的高 alpha。
3. **宽腐蚀 trimap + matting 重判边界**（closed-form / KNN / random walker，
   `probe_refine.py`）—— **全部更差**。trimap 的前景种子是 `alpha≥230`，
   而 isnet 给右边那只袜子的 alpha 只有 128~199，腐蚀之后右袜子基本被判成待定，
   抠出来半透明。出图：`out/06_refine_probe/`
4. **换模型**（`probe_models_gap.py`）—— `bria-rmbg` 和 `birefnet-general`
   一次就分开了，`birefnet-general-lite` 不行。
   出图：`out/10_model_gap/01_大花边__levels.jpg`（alpha 分层着色，
   只有这两格能看到两只袜子之间有黑色缝隙）

### 3. 语义闸门的判别力

`probe_gate.py` 在 core 阈值 32/64/96/128/150/180 上扫连通域：

- core=64 时鞋子碎片独立成域，sock 概率 0.158 / 0.294 / 0.336，全部低于 0.45 → 丢掉；
  袜子域 0.988 → 留下。
- core=32 时鞋子和袜子**连成一个域**，整体被判成 sock=0.945 → 会把鞋子一起留下。
  这说明连通域级的语义判断有前提：物体得先被 matte 分开。

22 张全量扫描里袜子和鞋子始终是独立连通域，判定余量 ≥0.37，所以判定规则定为
`sock ≥ 0.45 且领先第二名 ≥ 0.15`。
报告：`out/15_guarded/`（bria-rmbg）、`out/17_gate3_birefnet-general/`（默认模型）。

### 4. 转正的三道护栏

一开始只做「逐连通域 PCA → 倍角圆均值」，在单双平铺图上 7/7 正确，但：

| 图 | 主体细长度 | PCA 给的角度 | 实际 |
|----|-----------|-------------|------|
| SKU 01~08（单双平铺） | 1.53 ~ 2.11 | -20° ~ -31° | **对** |
| 主图_02（6 只密排站一行） | 1.39 | **-87.8°** | 转倒了 |
| 主图_01（一篮子袜子） | 1.12 | +44.1° | 错 |
| 主图_03（手拿一把袜子） | 1.14 | -25.1° | 错 |
| 904889/主图_02（两组袜子） | 1.51 / 3.09 | 两域差 **78.6°** | 合成结果无意义 |

密排那张的 mask 是个**实心矩形**，单只袜子的轮廓信息完全不存在 ——
这类图几何上不可能修对，只能识别出来别转。于是：

- `min_elongation = 1.45`（落在 1.39 和 1.53 之间）
- `max_axis_spread = 20°`（904889/主图_02 差 78.6°，直接否掉）

**但细长度这道护栏是跟着 matte 模型变的，单靠它不够。** 换成 birefnet-general
之后它的 mask 更干净、细长度更高：主图_02 从 1.39 升到 **1.47**，直接从 1.45
底下溜过去，被判成「可信」转了 -87.5°；904889 的 5 张对照图也是 2.45 / -78.2°。
证据：`out/_model_regression.jpg`。

所以补了第三道**与模型无关**的闸门：整图场景判断里
`max(many, packaged) - single_pair >= 0.20` 就不转。
这个信号只看整图、不看 matte，所以换模型不会失效。实测 22 张 ×2 个模型：

| | 该转/无害的 8 张 | 转错/无意义的 8 张 |
|---|---|---|
| 群图领先度 | **-0.58 ~ -0.04** | **+0.38 ~ +0.96** |

中间有 0.42 的空档，阈值取 0.20。加上这道之后**两个模型的转正结果完全一致**，
而且 04_条纹（群图领先度 -0.08，场景被误判成 many 但差距不大）的 -20.9°
转正被保住了 —— 这是只用场景硬闸门会误杀的那张。

三道都不过就**按 0° 处理**，并在结果里写明原因，绝不拿不可信的角度去转

### 5. 场景分类只用来挡「穿着图」

`probe_scene.py` 四分类（单品/多双/穿着/包装）对 22 张标注图只有 **59%** 准确率，
`many` 和 `packaged` 互相混。但降到「能不能当白底图源」的二分类是 20/22，
且**零误接受**。其中 `worn`（穿在脚/腿上）判得最干净：2/2 全中，
其他图的 worn 概率最高只到 0.172。

所以只有 `worn` 用作硬拒绝；`many` / `packaged` 不拒绝，只用来**关掉转正**
（见第 4 节的群图领先度闸门）——
直接按 top 类别硬拒的话，04_条纹（被判成 many，0.506）和 主图_04（被判成 many）
这两张好图会被误杀。

### 6. alpha 收紧能压掉多少毛边

`probe_tighten.py` 在 lo=0/0.28/0.40/0.55 四档对比蕾丝花边区域：
到 lo=0.55 蕾丝锯齿边仍然完整，说明这类模型的 alpha 够硬，收紧不吃产品细节；
但也说明剩下的毛边是模型**当成实前景**给进来的地毯纤维，收紧去不掉。
默认取 `lo=0.35`，软毛边收干净，离实测安全上限还有余量。

出图：`out/12_tighten/`

## 遗留问题

- 许可问题已解决：默认改用 MIT 许可的 `birefnet-general`。`bria-rmbg` 的权重是
  CC BY-NC 4.0（非商用），仍可用 `--matte bria-rmbg` 切过去，但商用要自己谈授权。
  `birefnet-general-lite`（213MB）分不开缝隙，**不能拿来当省体积的替代**。
- 一个商品 7 张图约 85 秒（birefnet-general 单张 ~12s，两轮聚焦）。
- 打包体积：onnxruntime + scipy + numpy 约 +280MB；模型 1.1GB 不打包。

## 脚本清单

| 脚本 | 用途 |
|------|------|
| `run_lab.py` | 主入口，批量跑流水线出成品 + 调试图 + report.json |
| `matte_compare.py` | 多模型 matte 并排对比 |

| `probe_gate.py` | 不同阈值下连通域怎么分裂 + CLIP 判别力 |
| `probe_scene.py` | 场景四分类准确率（带人工标注对照） |
| `probe_tighten.py` | alpha 收紧强度 vs 吃掉产品细节 |
| `smoke_api.py` | Sidecar 白底图接口冒烟（test_client，不抢 5001 端口） |
| `fetch_models.sh` / `fetch_seq.sh` / `fetch_clip.sh` | 早期的拉模型脚本（串行那版更快，别并行 5 路）；正式入口是 `python -m whitebg.setup_models` |

### 跑法

```powershell
# 全量扫描（22 张多场景图）
$B = "$env:LOCALAPPDATA\com.dyin.sock-publisher\uploads\products"
python lab/whitebg/scripts/run_lab.py --matte birefnet-general --out lab/whitebg/out/xx `
  --src "$B\ID-1075636304051\SKU" --src "$B\ID-1075636304051\主图" `
  --src "$B\ID-904889787428\SKU" --src "$B\ID-904889787428\主图"

# 只验几何，不加载 CLIP
python lab/whitebg/scripts/run_lab.py --no-clip --limit 3 --out lab/whitebg/out/geom

# 接口冒烟
python lab/whitebg/scripts/smoke_api.py          # 只查路由和防护
python lab/whitebg/scripts/smoke_api.py --run    # 连带真跑一次（约 80 秒）
```
