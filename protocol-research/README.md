# 协议自动化研究区

本目录用于承载抖店商品发布协议自动化的独立研究资产。

目标是基于当前正式 DOM 上传流水线，逐阶段挖掘页面背后的协议接口、字段结构、运行时 schema 和证据链；研究阶段不改动主项目正式链路，不接入正式上传按钮。

## 研究边界

- 默认先从页面运行态、schema、接口候选和已有产物入手；只要只读证据不足以继续推进，就直接切到受控 live 验证、真实页面交互和最小必要写接口实验，不人为把研究限制在“只读阶段”。
- 研究写接口时，允许在目标明确、影响范围可控、结果可观察的前提下执行真实写请求、真实页面动作、小步快跑实验，以及必要的真实提交到平台服务端；优先追求最快拿到真实请求体、真实响应体、真实页面回填和真实 blocker，而不是长期停留在 dry-run。
- 允许在当前已登录真实环境中直接使用 cookie、token、手机号、店铺信息和完整签名 URL 做现场排障与对照；但研究产物默认仍优先写去敏摘要，只有在“必须保留原始上下文才能继续推进”时，才额外保存原始材料，并明确标注用途、样本、时间和风险范围。
- 不通过伪造登录、绕过验证码、破坏风控或越权方式推进；优先直接利用当前真实已登录环境、真实页面和真实业务流程拿证据。
- 不把研究目录直接接入当前正式 DOM 上传流水线。
- 允许为继续推进实验而临时增加过渡性处理或受控兜底；但必须明确标注它是临时策略、适用前提和未闭环点，不能把它写成“字段已确认”或“协议已闭环”。

## 与主项目的关系

- 当前正式上传主线仍以 `tauri-app/python-sidecar/app.py` 中的 DOM 自动化为准。
- 本目录用于研究、文档、证据、映射和实验脚本，可直接驱动 live 页面与受控协议验证；但在证据未闭环前，不替换 `POST /api/upload/start` 背后的正式执行逻辑。
- 当且仅当某一协议阶段的证据闭环完整、字段来源可审计、受控 live 验证无关键 blocker 时，才有资格进入后续实现评估或主链接入评估。

## 当前研究主线

1. 回顾正式 DOM 上传流水线，拆出每个阶段的页面动作、输入输出和失败点。
2. 把每个 DOM 阶段映射到可能相关的只读接口、写接口和前端运行态模块。
3. 先补齐只读证据：类目、schema、运费、资质、素材、提交字段形状。
4. 再补齐写接口证据：最终提交、SKU/价格库存、媒体、资质。
5. 在研究目录内生成字段证据矩阵和 dry-run 对照，不接入主链路。

## 目录规划

- `docs/`：研究总览、DOM 上传流水线接口地图、阶段规划、复盘文档。
- `probes/`：只读探针和运行态分析脚本。
- `scripts/`：命令入口、批量执行脚本。
- `captures/`：本地截停后的去敏证据。
- `reports/`：阶段性结论、阻塞项、差异分析。
- `schemas/`：schema 摘要、多类目矩阵。
- `mappings/`：字段映射草案、阶段映射草案。
- `dry_run/`：拟提交模型、字段验证报告。
