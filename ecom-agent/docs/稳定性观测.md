# 稳定性观测

> **「现在能用」不等于「一直能用」。**
>
> 可行性表回答「这个能力存不存在」，是一次性的。
> 本文回答「它能不能被稳定依赖」，**必须长期重复跑才有意义**。
>
> 复现：`node probe/stability.js`
> 看趋势：`node probe/stability.js --report`

---

## 测什么

| 维度 | 为什么要测 |
|---|---|
| **可用率** | 平台会限流、会风控。今天 100% 不代表明天 |
| **值一致性** | 已定稿窗口多次调用应当完全相同。不一致 = 结论不可复现、无法复核 |
| **结构指纹** | 平台改版会让字段增删改名。**值还在但解析器已经静默失效**，光看「有没有数据」发现不了 |
| **延迟分布** | p50 与 max 决定超时该设多少。实测 max 到过 17 秒 |

## 不做什么

**默认不压测。** 密集调用会触发反爬 `10001010A`，把正常业务一起拖下水。
要探限流阈值请显式 `--stress`，并且知道自己在做什么。

## 这次观测查出的两个真问题

### 一、多字节字符在分块边界被截断（已修）

**现象**：热点榜连续 3 次调用返回 3 种不同结果，看起来像「平台数据不稳定」。

**真相**：视频标题「帮人**修**表」在某些响应里变成「帮人**??**表」。

**根因**：`lib/compass_cookie.js` 用 `d += c` 逐块拼接——
每个 Buffer 分块**各自**转成字符串再拼。一个多字节 UTF-8 字符若跨在
两个分块边界上，两半各自解码就成了乱码。

```js
// 错：分块各自解码
let d = ''; res.on('data', c => d += c);

// 对：先拼 Buffer，最后整体解码
const chunks = [];
res.on('data', c => chunks.push(Buffer.isBuffer(c) ? c : Buffer.from(c)));
res.on('end', () => resolve(Buffer.concat(chunks).toString('utf8')));
```

**危害**：会静默损坏商品标题、搜索词、达人昵称这类文本，
而且**只在部分响应里出现**——极易被误判成平台问题。

已修并加自检断言（89 项全绿）。

### 二、CDN 域名轮换会造成假的「数据不稳定」

图片 URL 的 CDN 主机在 `p3` / `p11` / `p26`.douyinpic.com 之间轮换。
把它算进值指纹，同一份数据会得出 3 个不同哈希。

**一个会对 CDN 轮换报警的稳定性探针，只会让人学会忽略它的警报。**

已在值指纹里归一化主机名，路径保留（路径变了是真的变了）。
六种情形验证：三种 URL 形式的轮换不误报，路径/数值/文本的真实变化不漏检。

## 探针自己也会骗人

写这份观测的过程中，探针误报了 **3 次**：

| 误报 | 真相 |
|---|---|
| 值不一致（3 种结果） | CDN 域名轮换 |
| 值不一致（仍有 2 种） | URL 正则漏了协议相对写法 `//host` |
| 深度比对说「0 处差异」 | 比对限深 6 层，差异藏在更深处 |

第三条尤其阴险：**两个工具给出相反结论时，不能挑一个信**。
最后是用探针自己的归一化逻辑输出 JSON、直接对拍字符串才定位到。

**规矩：稳定性探针报出的异常，先自证探针没错，再下结论。**

## 已知的不稳定来源

| 现象 | 性质 | 应对 |
|---|---|---|
| `10001010A` 当前环境存在风险 | 反爬风控 | **重试无用**，需换环境或等冷却。密集调用会触发 |
| `st=100704` 服务器错误 | 平台瞬时 | 刷新会话可恢复（`isRetryableSessionError` 已覆盖） |
| `st=11001` 网络不稳定 | 限流 | 退避，不要立刻重试 |
| 首次调用 9–17 秒 | 会话建立 | 超时按 max 设，不能按 p50 |

---

## 使用约定

1. **按天跑一次**，累积到 `probe/stability_history.jsonl`
2. `--report` 看趋势：可用率下滑、结构指纹变过，都要复核
3. **结构指纹变了必须停下来查**——那是平台改版的信号，
   此时数据可能照常有，但解析出来的含义已经不对了
4. 上线新节点前，先确认它依赖的端点在本表里有足够观测轮次
