## 安全截停模式

新增工具：`cdp_fxg_protocol_capture` / `npm run capture:fxg-protocol`。

默认模式只观察匹配请求，不主动触发上传、保存或提交。显式开启 `blockMatchedRequests` 时，工具会：

1. 通过 CDP Fetch 拦截匹配 URL。
2. 记录去敏后的请求摘要。
3. 在请求到达平台服务端前中止请求。

示例：

```powershell
Set-Location '<project-root>\mcp-server'
$env:DURATION_MS = '15000'
$env:BLOCK_MATCHED_REQUESTS = '1'
$env:BLOCK_URL_PATTERNS = '/product/tproduct/addWithSchema,/product/tproduct/submitWhiteImg'
npm run capture:fxg-protocol
```

注意：该模式会让页面对应操作失败，这是预期现象。它的目标是确认请求体结构，不是完成页面操作。

  - `property_785_item_keys_reordered` 仅重排 `category_properties["785"][i]` 内键顺序
  这三类**不改任何业务值**的变体也都会返回 `code=10001010A`。
- 与之相对，`baseline` 和 `swap_order` 仍返回 `code=10013 / 内容未修改`。这说明当前风控边界不能再简单概括为“只拦真实语义改动”；至少在编辑态 `editWithSchema` replay 下，部分请求体原始序列化形态变化本身也足以触发异常发品风控。
- 因此当前首先命中的仍不是 `measure_info` 字段级错误，但应把结论修正为：`editWithSchema` 编辑态 replay 对请求体改写高度敏感，敏感点既包含业务语义值，也包含至少一部分 JSON 原始形态；`785` 的细粒度后端校验规则仍未直接暴露。

## 下一步顺序

1. 固化只读探针，持续验证类目、规格轴、SKU 列、资质子项和运费模板。
2. 优先继续补齐 `submitWhiteImg`、`saveMaterial` 的**真实触发条件**与请求体，并把已拿到的成功 `addWithSchema` 样例拆成更细颗粒字段证据。
3. 在 dry-run 中把“已验证字段”和“候选字段”分开输出。
4. 只有当 dry-run 能解释每个字段来源，并且本地预检与页面真实结构一致时，才考虑接入低风险协议阶段。
5. 正式发布仍保留 DOM 流水线，直到协议链路完整闭环。

## 禁止事项

- 禁止用静态 HTML 文件推断最终协议入参。
- 禁止用兜底代码掩盖字段映射错误。
- 禁止在字段证据不足时把“合格证”硬编码成平台资质字段。
- 禁止在正式上传中默认启用未验证协议写入。
- 禁止把本地预检模式描述成绕过平台校验或审核。
