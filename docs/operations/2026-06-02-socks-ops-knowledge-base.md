## 使用边界

- 本文用于指导当前抖店袜子经营闭环，不调用抖店官方 API，不调用外部 AI。

- 所有经营动作先走只读诊断、本地测算和安全闸；最终发布、付款、投放扣费仍需人工确认。

## 运营动作优先级

1. 详情承接优先：详情页前半段必须先说明上脚场景、材质厚薄、适穿鞋型、洗护和退换规则，减少点击后的犹豫。
2. 规格降错：SKU 明确 `1双`、均码、颜色和默认发货规则，详情页和规格图继续强化售卖单位。
3. 主图视频承接：已有点击但无成交时，主图视频不只为点击率服务，还要在首帧和前 3 秒表达真实上脚、颜色和 1 双口径。
4. 搜索承接：标题保留“女款、浅口、船袜、春夏、薄款、可爱、短袜、均码”等核心词，不堆无关词。
5. 低库存试卖：上架前维持每 SKU 2 件、总 20 件的保守备货；没有成交前不扩大备货。
6. 广告闸口：有 1 个点击但 0 成交时继续暂停付费广告；必须先证明点击能转化为订单且单笔净利为正。
7. 平台素材闸口：主图视频已本地生成，但平台上传预检和平台素材验收未验证，不能算平台侧问题已解决。
8. 品牌安全闸口：当前袜子商品统一设置为 `无品牌`；标题区 `使用品牌名` 保持关闭，不猜测品牌、不借用品牌词、不为了搜索流量冒用品牌。

## 商品卡点击瓶颈规则

当 `product_exposure_count > 0` 且 `product_click_count = 0` 时，系统应判定为 `card_click_bottleneck`，不是利润瓶颈，也不是投放瓶颈。

执行顺序：

1. 首图：先给上脚效果、颜色差异和 `1双` 信息，减少用户看不懂商品卡。
2. 主图视频：首帧展示上脚效果，后续展示颜色、刺绣和叠放细节。
3. 标题关键词：围绕搜索曝光词保留核心意图词，不追求长标题堆词。
4. 价格展示：确认售价和 SKU 口径一致，低价袜子尤其要明确是 `1双` 还是组合装。

补充安全规则：

- 若商品本身没有可证明品牌资质，类目属性只选 `无品牌`。
- 标题和导购短标题不写品牌词，不勾选平台标题区的 `使用品牌名`。
- 自动化实现层忽略本地记录、货源导入或旧命令传入的具体品牌值，发布前统一映射为 `无品牌`。
- 关键词扩展也遵守无品牌策略，不生成 `哪个牌子好`、`品牌推荐`、`防臭袜子品牌` 这类品牌比较词。
- 每次处理商品诊断待办前先运行 `ops_no_brand_title_audit`；若标题含来源品牌残留，只能先只读确认线上品牌字段和标题来源，不得直接上传素材或保存。
- `jk`、`ins` 这类风格/穿搭词不是品牌词，审计不能把它们误判为品牌残留。
- 品牌相关变更只允许在用户提供真实品牌授权、资质材料并明确要求后再处理。
- 在没有品牌资质时，安全稳健优先于短期搜索词覆盖。
- 公开报道显示抖音电商近期继续加强品牌资质和虚假品牌宣传治理；对当前无品牌袜子店铺，稳健做法是只卖真实无品牌商品，不用“假洋牌”、极限词或无法证明的授权背书。参考：[新浪财经转载上游新闻：抖音电商上线跨境品牌资质新规](https://finance.sina.cn/stock/jdts/2026-05-27/detail-inhzieiu0872253.d.html)

验收口径：

- 下一次只读经营快照中 `product_click_count > 0` 或 `product_click_rate > 0`，才能认为商品卡优化开始产生点击信号。
- 如果有点击仍无成交，则阶段切换为 `detail_conversion_bottleneck`，重点转到详情页承接、SKU 清晰度、运费、售价和退换说明。
- 在点击仍为 0 时，不开启付费投放；否则只是付费买无效曝光，不能帮助验证日净利目标。

## 详情承接瓶颈规则

当 `product_click_count > 0` 且 `orders_count = 0` 时，系统应判定为 `detail_conversion_bottleneck`。当前 2026-06-03 08:53 快照正处于该阶段：`18` 曝光、`1` 点击、`0` 成交、搜索曝光 `255`。

执行顺序：

1. 详情页前半段：先写清真实上脚场景、适穿鞋型、材质厚薄、是否薄款透气、洗护和退换说明，避免用户点击后仍不知道是否适合自己。
2. SKU 与规格图：SKU 名称和规格图必须明确 `1双`、均码、颜色、默认发货规则；低客单袜子尤其要避免用户误以为是多双组合。
3. 主图视频承接：视频候选只使用商品已有素材或自有素材，本地预检通过后再进入编辑页；未保存线上商品前不把素材问题记为已修复。
4. 运费与售价：继续核对售价、运费、平台佣金、包装和售后损失，保证点击转订单后单笔净利仍为正。

验收口径：

- 下一次只读经营快照中 `orders_count > 0`，才能认为详情承接开始转正。
- 如果出现订单，立即进入 `profit_validation`：同步订单、退款、售后、真实运费、佣金和推广消耗。
- 如果继续只有点击无订单，不加广告，先继续拆解详情页、SKU 和退换说明。

## 商品诊断信号规则

`ops_read_strategy_signals_cdp` 通过浏览器 CDP 读取抖店页面可见文本，可识别：

- 在售商品数、优秀商品数。
- 缺主图视频商品数。
- 缺规格图商品数。
- 缺直播讲解回放商品数。
- 风险商品数。
- 明确标注的机会词。
- 售后原因中的 `多拍/错拍/不想要`。
- 商品诊断表中的具体问题商品：标题、抖店商品 ID、质量分、近 30 天销量和推荐问题。

执行原则：

- 缺主图视频和缺规格图属于商品素材质量问题，应优先于付费投放。
- 缺讲解回放对低客单袜子先记录，不作为当前强制直播依赖；除非后续出现高曝光高点击但仍无成交。
- 风险商品只做只读核对和素材/规则风险排除，不能直接点击平台“一键优化”或托管按钮。
- 机会词只从页面明确标注的机会词区域提取，不把普通商品标题或店铺名当成机会词。
- 这些信号进入 `diagnostic_action_plan` 后，再和 `growth_bottleneck_plan` 一起决定当天动作。
- 当存在具体问题商品时，按近 30 天销量优先处理，先修有销量或曝光基础的商品；没有销量的商品优先补规格图、发货口径和基础素材。
- 页面上的 `立即优化`、`一键优化`、标题优化托管等按钮不自动点击，只作为只读诊断线索。
- `ops_sync_strategy_signals` 用于把上述诊断信号持久化到本地运营账本，并生成 `open` 状态的商品问题待办；它只写本地 SQLite，不向抖店提交优化、发布、投放或托管动作。
- 每次诊断入账后，应回到首页再同步经营快照，避免后续把诊断页当成经营首页读取。
- 如果当前主标签页停留在未保存编辑页，经营快照必须使用 CDP 临时首页 tab 读取：打开 `ffa/mshop/homepage/index`、读取可见指标、关闭临时 tab，并确认原编辑页仍保留。
- `ops_read_shop_metrics_cdp` / `ops_sync_shop_metrics` 支持 `useTemporaryTab=true`；默认读当前页，只有需要保护未保存编辑页时才打开临时 tab。
- `ops_sync_product_record_mappings` 用于把线上诊断商品与本地 `Record` 做保守标题相似度匹配；低于阈值时必须标记 `unmatched`，不能强行复用无关素材。
- 当映射为 `unmatched` 时，素材修复动作应标记为局部 `blocked` 或保持 `open`，下一步是只读进入线上编辑页确认素材来源，或重新导入该商品素材。
- open 待办必须先分流：`active_save_gate`、`blocked_material_mapping`、`blocked_brand_risk`、`open_missing_material`；不能把“标题安全”误认为“素材可执行”。
- 商品管理页读到的售价、库存、销量、质量分和商品图片只作为页面证据；如果编辑入口没有安全进入，不能把“已定位商品”当成“可执行修复”。
- 进入线上编辑页后仍只允许只读确认或截停式预检；保存、下架、投放、付款、发布等不可逆动作必须保留用户安全闸。
- 上传前必须先运行 `ops_publish_preflight_safety`：确认当前页是目标商品编辑页、品牌为 `无品牌`、标题区 `使用品牌名` 关闭、候选素材存在、没有可见引导浮层；即使通过，也只表示可进入“上传素材并截停”，不代表可以保存、发布、投放或付款。
- 主图视频只允许通过 `ops_upload_main_video_preflight` 做截停式上传：触发本地候选视频上传后必须停在保存/发布前，并记录 `mutation_type=main_video_upload_only`、`no_save=true`、`no_publish=true`、`no_ad_or_payment=true`。
- 上传截停成功不等于线上商品已生效；未点击保存或发布前，商品问题待办保持 `in_progress`，不能标记 `done`。
- 后续只读预检不能覆盖已有上传证据；如果 action evidence 已包含 `main_video_upload_only` 或 `upload_result`，只能追加 `latest_preflight`，不得把 `shop_mutation=true` 降级成 `no_upload=true`。
- 保存当前编辑页前必须先运行 `ops_save_edit_human_gate`：确认无品牌预检通过、主图视频已上传确认、页面存在成功素材卡、没有上传中状态、没有浮层 blocker。
- `ops_save_edit_human_gate` 只表示“可以请求用户确认保存”，不表示系统可以自动保存；`safe_to_auto_save` 必须保持 `false`。
- 用户明确确认保存后，也只允许保存当前编辑页；发布商品、保存草稿、填写检查、投放、付款仍是单独安全闸。
- 有点击但无订单时运行 `ops_detail_conversion_audit`：把当前编辑页读到的导购短标题、重要属性、材质成分、规格图、SKU、运费和售后政策转成详情承接待办。
- `ops_detail_conversion_audit` 是只读审计，不自动填表、不保存、不发布；结果中的 `safe_to_auto_save` 必须保持 `false`。
- `ops_detail_conversion_audit` 必须能从浏览器 `body_text`、`visible_fields` 和 `main_video_field` 派生详情字段；不要要求调用方手工拼装颜色、尺码、库存、属性进度等字段。
- 品牌闸判断不能只依赖窄范围 `brand_text`；如果完整页面文本或可见字段明确包含 `*品牌 无品牌`，且 `使用品牌名=false`，应判定无品牌闸通过，避免标题区文本造成误报。
- 页面里的 `付款减库存` 是库存计数方式，不是付款动作；安全审计不能把它误判为付款按钮，但 `发布商品`、`保存草稿`、`填写检查` 仍属于保存/发布前禁区。
- `ops_detail_conversion_audit.suggestions` 只作为本地草案：导购短标题和属性建议必须无品牌，且不能自动应用。

- 主图/视频/规格图必须真实表达售卖单位、颜色、均码和默认发货规则；不能为了点击制造与实际发货不一致的画面。

## 到 500 元日净利的阶段路径

### 阶段 1：0 点击到有点击

- 目标：商品点击人数从 0 变为大于 0。
- 动作：优化首图/主图视频/标题关键词；不投付费广告。
- 验证：通过抖店首页或经营数据读取商品曝光人数、商品点击人数。

### 阶段 2：有点击到首单

- 目标：成交订单数从 0 变为大于 0。
- 动作：复核详情页、SKU 选择、价格、运费、退换说明；保持低库存试卖。
- 验证：订单明细和售后/退款读数。

### 阶段 3：首单到稳定转化

- 目标：明确单笔净利、点击转化率和退款损失。
- 动作：按真实订单修正成本、运费、佣金、退款损失；筛选高净利 SKU。
- 验证：经营净利或完整成本公式账本。

### 阶段 4：稳定转化到 500 元日净利

- 目标：围绕单笔净利 2.95 元的候选商品，验证是否能逐步接近约 170 单/日；若达不到，则必须提升客单价、组合装或选品毛利。
- 动作：只在自然点击和首单验证后做低预算推广；逐步补货，不压库存。
- 验证：经营净利字段或订单、成本、退款、推广消耗全量公式。
