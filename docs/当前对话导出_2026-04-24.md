### 白底图组件懒加载扫描

本次断点之后继续读取了真实页面 webpack 模块。

第一页只加载模块 `55060` 和部分基础模块，未加载白底图实际组件调用点。

随后只读加载 chunk `2492`：

- chunk：`goods-components-MaterialImg`
- 新增模块数量：3304 -> 3307
- 重点模块：`9559`

模块 `9559` 结论：

- 导出组件：`MaterialImg`
- 组件字段：`form_key:["white_background_pic"]`
- 前端 UI 文案：白底图。
- 上传值映射：
  - `mapValue`: `(value || []).map(item => item.url)`
  - `onUpdateValue`: `url[] -> [{ url }]`
- 白底图校验流程：
  - 先通过 `D.QG(url, aspects)` 做比例/裁剪相关校验。
  - 再通过 `K.K(urls, { shop_id, product_id, product_name })` 做高质量白底图识别。
  - 返回大致结构：`{ passed, value, reject_reasons }`
  - 组件内部最终仍写入 `white_background_pic: [{ url }]`
- 申诉/送审白底图：
  - 调用 `/product/tproduct/batchApprovalWhiteImgs`
  - 请求体：

```json
{
  "approval_materials": [
    {
      "product_id": "...",
      "material_id": "...",
      "material_type": 1
    }
  ]
}
```

重要发现：

- `goods-components-MaterialImg` 里没有直接调用 `submitWhiteImg`。
- `submitWhiteImg.action_list` 在当前第一页 + 懒加载 `MaterialImg` 的静态源码里仍未定位。
- 更可能需要进入第二页或触发具体白底图相关操作后，另一个组件/流程才会加载 `submitWhiteImg` 上层调用点。
