### 12. 批量淘宝发布的三个既有问题（2026-10-21）：行为修改，不是搬迁

第五轮搬迁淘宝发布时发现了三个既有问题（「5. 未决问题」第 20~22 条），按「搬迁和逻辑修改分开做」的约定当时一行没改。这一节把它们作为**独立的行为修改**修掉。
URL、方法、JSON 结构都没变（128 条路由快照不受影响）；只动了 `src/sidecar/taobao_{helpers,service,routes}.py` 和对应测试，没碰 `app.py`、其它业务域和前端。

#### 12.1 改了什么

| 问题 | 位置 | 改法 |
|---|---|---|
| 第 20 条：批量发布给流水线的类目关键词是 `'2'` | `taobao_helpers._taobao_product_from_record` | `Record.clazz` 是 `CharField`，从库里读出来是字符串（整数 2 存进去、读出来是 `'2'`），而原来只有整数才映射成名称。现在「去掉首尾空白后全是 ASCII 数字」的字符串先转成整数，再走原来的整数映射（`_CATEGORY_LABELS`）：`'2'` / `' 2 '` → `中筒袜`；认不得的代码（`'9'`、`'99999999999999999999'`）仍给空串；文字类目（`' 短袜 '` → `短袜`、`'2号'` 原样）不变；`'²'` / `'２'` 这类非 ASCII 数字不当代码（`'²'.isdigit()` 为真，但 `int('²')` 会抛）。 |
| 第 21 条：`start-all` 没有准入检查 | `taobao_routes.taobao_publish_start_all` | 与 `taobao_publish_start` 同一套：① 先过 `accounts.account_change_blocked()`，位置在 `service.ensure_fill_browser()` 之前（批量也要拉起账户的素材中心浏览器，而 `ensure_fill_browser` 的文档写明调用方得先确认没有发布任务在跑）；② 再在**同一把 `service.lock`** 里查 `pending` / `running` 的任务并登记，已有任务时 409：`已有一个淘宝发布任务在进行中（<id>，<名称>），请等它结束后再发起`。 |
| 第 22 条：批量 worker 一直是 `pending`，翻译异常让线程崩溃 | `taobao_service.run_publish_batch_task`（现在是外层兜底，主体搬到 `_publish_batch`） | ① 开始时置 `running` 并写 `started_at`；② 每条记录的「构造载荷 + 资料翻译」挪进 per-record 的 `try`：失败记成该条 `results` 里的 `类型名: 消息`、计入 `failed`、继续下一条；③ 外层再兜一层：`_publish_batch` 里其它意外（比如读不出待发布列表）让任务以 `failed` 结束——`淘宝批量发布失败` + `error` + 结束时间，回溯打到 stderr，和单品 worker 同一口径。结果：任务一定以 `succeeded` / `failed` / `cancelled` 之一结束，`pending` / `running` 不会再被遗弃在那里去挡账户切换、保存该商品和单品发布。 |

几个取舍：

1. **准入检查在 `start-all` 里同形再写了一遍，没抽成两个路由共用的函数。** `test_sidecar_taobao_concurrency.py` 用 AST 钉着 `taobao_publish_start` 自己的函数体（「`in_flight` + 同一个 `with service.lock` 里查 + 插」、整个函数里只有一处 `service.lock` 块）；抽成共用函数就得连这些结构测试一起改写。
   代价是约 10 行重复，换来的是 `start` 一行没动，结构测试对 `start-all` 同样钉死（新增 `TaobaoBatchPublishAdmissionTest`）。
2. **`account_change_blocked()` 不能写进 `with service.lock:` 里面**：它内部（经 `app.py` 的 `_publish_tasks_running()`）读任务表也要拿 `service.lock`，那是不可重入的 `threading.Lock`，写进去请求会把自己锁死。结构测试里有一条专门检查它在锁外、且早于 `ensure_fill_browser()`。
3. **per-record 的 `except` 仍是 `except Exception`**（原来就是），所以翻译抛什么都记到这一条上（带类型名），没有缩成只认 `ValueError`；外层兜底只管「不属于任何一条记录」的意外。两层都不是吞错：每条失败在 `results` / `error` 里都有原文，外层还把回溯打到 stderr。
4. **提示语沿用既有的两句。** 有发布任务在跑时，生产里 `account_change_blocked()` 先拦下，提示是「发布任务运行中，请完成或取消后再切换账户」——这是账户切换互斥的通用文案，单品填写任务走同一道门时也是它，对「再起一个批量」措辞不太贴切，没改。
   锁内查的那一句（`已有一个淘宝发布任务在进行中……`）在 `start-all` 里是「查 + 插」原子性的保证，前面的互斥先拦下时用不上；单品发布的非填写路径（校对）不过账户切换互斥，那里它才是实际的准入。
5. **没动的邻居**：批量 worker 里「任务从表里消失后仍会逐条处理记录」（`test_a_vanished_batch_task_is_ignored` 钉着；生产里没有删任务的代码，走不到）；批量 worker 结束时不还原 `TAOBAO_MEDIA_ROUTE`（这次实测发现的，见「5. 未决问题」第 25 条；当时没改，同日作为单独一步补修了，见 12.6）。
