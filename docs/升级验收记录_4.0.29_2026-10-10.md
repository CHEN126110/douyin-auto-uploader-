## 三、升级测试怎么做

客户端更新是 GUI 交互（弹窗确认），因此测试夹具不冒充正式 4.0.28 安装包，而是：

1. 用 `f16b4e1` 的源码树构建一份**基线程序**，把版本号降回 `4.0.28`、换回**上一版更新器实现**
   （`updater.ts`），更新源指向候选 `latest.json`，并把安装目标限定在隔离目录。
2. 基线安装到 `.tmp/release-4.0.29/installed-app/`，数据目录指向
   `.tmp/release-4.0.29/upgrade-data/`（经 `DOUYIN_DATA_DIR`），WebView2 资料目录一并隔离。
3. 启动基线 → 让**它自己**完成检查、下载、验签、安装。

驱动方式是 UI Automation 读 WebView2 无障碍树 + 调用真实按钮（`运行` 由 Win32 `BM_CLICK` 完成），
不注入任何业务逻辑。日志与状态快照落在 `.tmp/release-4.0.29/upgrade-run/`。

## 四、需要知道的三件事

1. **更新时会弹一次 Windows「打开文件 - 安全警告 / 无法验证发布者」。** 点「运行」即可继续，
   之后仍会过内嵌公钥的 minisign 验签。成因是 `tauri-plugin-updater` 在 Windows 上以
   `ShellExecuteW` 启动安装器（`updater.rs` 的 install 分支），而本机
   `HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\Attachments\ScanWithAntiVirus=3`
   会拦一次；安装包本身没有 `Zone.Identifier`。本版没有改动更新器插件版本（`tauri-plugin-updater`
   仍为 2.9.0），与本次代码改动无关。自动化脚本要注意：`Start-Process` 会一直阻塞在这个对话框上，
   改用 `cmd /c start`。
2. **本地开发机的 `target/release/douyin-sock-publisher.exe` 仍是 4.0.28 的旧构建**（测试前后哈希一致，
   已从 `tauri-app/_sidecar_backups/release-4.0.29/` 还原）。它启动后会从正式链路看到 4.0.29，
   想立刻用上需重新构建或安装新版。
3. **验收过程中有一次误操作导致测试商品记录被删。** 前台窗口在测试期间收到过一次界面交互，
   触发了「删除商品」并弹出「删除成功」；只影响隔离目录里的测试记录，未触及文件与真实数据。
   随后的对照实验（恢复记录 → 启动 → 120 秒不做任何界面交互）显示记录稳定存在，
   且单纯的无障碍探测不会触发删除，因此**不是 4.0.29 的启动丢数据缺陷**。

## 五、本轮一并修掉与留下的

- 修掉：`tests/test_shop_session.py`、`tests/test_upload_browser_profile.py` 里两条比较**路径字符串拼写**的断言，
  改为比较目录身份（`os.path.realpath`）。Windows 会把同一路径同时表示成长名与 8.3 短名，产线代码统一返回
  规范化长名、`tempfile` 返回环境里的短名，于是短名机器上必然失败。本机以短名 TEMP 复现出与 CI run #2
  完全一致的失败后修正，同一环境转绿。
- 留下（不影响 CI）：`taobao-publisher/scripts/check-sidecar-freshness.py` 的 `SKIP_DIRS` 含通用名 `tmp`，
  因此把 `TEMP` 指到仓库内 `taobao-publisher/tmp/...` 时，`test_sidecar_freshness.py` 等 3 个用例会因
  合成文件被跳过而失败。CI 用 runner 的临时目录，不受影响；本地跑测试时不要把 `TEMP` 指进仓库的 `tmp`。
