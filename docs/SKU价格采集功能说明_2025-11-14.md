## 一、功能概述

在采集淘宝/天猫商品时，系统现在会自动采集每个SKU的价格，并将价格自动填入到SKU价格输入框中。

## 二、采集流程

### 2.1 价格采集策略

采用**智能三步采集法**，确保获取准确价格：

#### 第一步：获取默认价格

```javascript
// 从商品页面主价格区域提取默认价格
var priceElem = document.querySelector('.highlightPrice--asfw5V1e') || 
                document.querySelector('.tb-rmb-num');
```

#### 第二步：点击SKU获取准确价格

```python
# 依次点击每个SKU选项（最多10个）
for sku in same_type_skus[:10]:
    click_sku(sku.vid)  # 点击SKU
    wait(0.3秒)         # 等待价格更新
    get_updated_price() # 获取更新后的价格
```

#### 第三步：匹配价格到SKU

```python
# 根据SKU名称匹配采集到的价格
for captured_sku in captured_sku_info:
    if captured_sku.name == sku.name:
        sku.price = captured_sku.price
```

### 2.2 采集优化

✅ **性能优化**

- 只点击第一个SKU类型（通常是颜色）
- 最多点击10个SKU，避免采集时间过长
- 跳过已禁用的SKU选项

✅ **容错处理**

- 如果点击失败，使用默认价格
- 如果价格提取失败，使用默认价格
- 所有异常都有日志记录

## 六、注意事项

### 6.1 价格准确性

⚠️ **价格可能存在的情况：**

1. **统一价格**：所有SKU价格相同
  - 采集结果：所有SKU显示相同价格
  - 原因：商家未设置不同颜色的差异价格
2. **差异价格**：不同SKU价格不同
  - 采集结果：每个SKU显示对应价格
  - 原因：商家为不同颜色设置了不同价格
3. **部分SKU无价格**：某些SKU可能无法点击
  - 采集结果：使用默认价格
  - 原因：该SKU可能已售罄或被禁用

### 6.2 采集性能

⚠️ **性能优化策略：**

- ✅ 最多点击10个SKU（防止采集时间过长）
- ✅ 每次点击等待0.3秒（足够价格更新）
- ✅ 只点击第一个SKU类型（通常是颜色）

**预计采集时间：**

- 10个SKU：约3-4秒（10 × 0.3秒 + 网络延迟）
- 如果商品有多个SKU类型，会使用默认价格（不点击）

### 6.3 价格验证建议

⚠️ **采集后请验证：**

1. 打开采集的商品详情
2. 检查SKU价格输入框
3. 对比淘宝/天猫页面的价格
4. 如有差异，可手动修改价格

## 七、常见问题

### Q1: 为什么有些SKU价格是0？

**可能原因：**

- 该SKU在淘宝/天猫页面已售罄或禁用
- 网络延迟导致价格未及时加载
- 页面结构变化导致选择器失效

**解决方法：**

- 手动填入价格
- 使用智能价格计算功能
- 重新采集商品

### Q2: 价格不准确怎么办？

**解决方法：**

1. 检查淘宝/天猫原页面的价格
2. 在SKU列表中手动修改价格
3. 使用智能价格计算功能批量设置

### Q3: 采集时间很长？

**原因：**

- SKU数量较多（>10个）
- 每个SKU需要点击和等待

**优化：**

- 当前已优化为最多点击10个
- 只点击第一个SKU类型
- 采集时间基本控制在5秒内
