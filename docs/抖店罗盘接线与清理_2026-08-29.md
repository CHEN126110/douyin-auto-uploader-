# 电商罗盘接线与仓库整理（2026-08-29）

## 起因

独立对抗性审查的核心结论：**Agent 调不到这些数据**。

`scripts/compass/compass_api.js` 攒了 85 个端点函数，但 `lib/tool-registry.js`
不加载它；`lib/doudian.js` 虽 require 它，却只借用 `init/close/setUserConfig`
三个会话函数。同样，`lib/compass_unwrap.js` 与 `lib/data-contract.js`
全仓只被 `selfcheck.js` 引用——**加固不在真实数据路径上**。

## 一、接线

### 新增 `lib/compass_tools.js`

```
compass_api（取数） → compass_unwrap（解包） → data-contract（定性）
                                                    ↓
                                   tool-registry → dispatcher → Agent
```

- 目录只收录**实测能返回真实数据**的端点
- 按端点路径与既有 `diagnosis.compass.*` 去重，**剔除 21 个重复**，保留 46 个
- 每个结果带 `_meta`：`scope` / `canDriveDecision` / `advisory`

### 旧路径也接上了

`dispatcher._callCompass` 增加 `annotateCompass()`，给 27 个既有工具补挂
`_unwrapped` 与 `_meta`。**只做加法不改 `data`**——直接替换风险太高，
解包器一旦漏解某种结构就会静默丢掉整块指标。

### 作用域补登

`data-contract.SOURCE_SCOPES` 从 20 条补到 39 条，
27 个 `diagnosis.compass.*` **全部登记**（原本 19 个未登记，被 fail-closed
一律挡住——fail-closed 是对的，但把可用的市场数据也挡了，等于契约没起作用）。

### 实测结果

| | |
|---|---|
| ✅ 有业务数据 | **31** |
| 📊 平台只给图表 | 2（`shop.core_trend`、`trade.core_trend`） |
| ⚠️ 解包器盲区 | **0** |

## 二、修掉的假数据源

| 位置 | 问题 | 后果 |
|---|---|---|
| `lib/attribution.js:11` | `extractNum` 只认 `typeof v.value==='number'` | 平台大量 `{value:750000000, value_str:''}` 节点被静默解成 null；且 null 同时表示「未就绪」与「结构不认识」 |
| `scripts/infra/workbench_server.js` | 7 处 `?.value \|\| 0` | `unit=6`（数据未就绪）落成 0——仪表盘上「今天 GMV 0 元」与「数据还没出」是两回事 |
| `lib/compass_unwrap.js` | `meta[].children` 被当数据行 | 解出一批字段名齐全、值全 null 的**假行**，下游看到「有 5 行、共 N 条」 |
| `lib/compass_unwrap.js` | 图表型静默返回 `{}` | 调用方分不清「我们没解」和「平台没给」 |
| `lib/compass_cookie.js:142` | 只查 `code`/`st` 两个字段 | `status_code`/`err_no`/`errNo` 一律放行，错误信封当数据返回 |

**「表头当数据」我在这一个会话里犯了三次**：health_audit 的 `ok_with_data`、
`summarize` 把 `__columns` 数组当行数、`meta` 列定义当数据行。
每次都长得像「有数据」。现已加 5 项断言锁死，并验证过断言真能咬人。

## 三、空数据的三种原因

混为一谈是假数据的温床，现已分开：

| `reason` | 含义 | 处置 |
|---|---|---|
| `platform_empty` | 平台确无数据 | 不可据此认定「该指标为 0」 |
| `chart_only` | 平台只给图表坐标 | 该端点不提供明细，换端点 |
| `unparsed_shape` | **解包器盲区** | 我们的 bug，需补分支 |

## 四、重复实现收敛

独立盘点查出 **13 处**信封解析实现（不是此前以为的 8 处）。

新增 `lib/envelope.js` 作单一真源，`doudian.js`、`compass_api.js`、
`compass_cookie.js`、`compass_pool.js` 全部改为引用。
死代码 `_compassBrowserGet`（零调用点）移出。

### 踩坑记录：合并码表要取并集

统一鉴权码时我取了 `compass_api` 的集合，**漏掉 `compass_cookie` 独有的
`st=100704`**，导致整条 `compass_pool`/`compass_cookie` 通道全线「服务器错误」——
因为 100704 原本靠刷新会话重试一次恢复，重试没了。

盘点报告其实明确建议过「按并集统一」，我取成了单边。
现已引入 `RETRYABLE_SESSION_CODES = AUTH_CODES ∪ {10012, 100704}`。

> **合并两份配置时，默认取并集；取单边必须逐项说明被丢弃的那些为什么可以丢。**
