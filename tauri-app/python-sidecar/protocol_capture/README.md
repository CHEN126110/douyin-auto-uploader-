# 协议化采集引擎

这个目录用于承载货源侧的协议化采集主线。

范围包括：

- 1688
- 淘宝
- 天猫

## 目标

把当前“浏览器打开页面后混合 DOM 提取 + 图片下载 + 导入回填”的采集方式，升级为独立、可调试、可审计、可分平台演进的协议化采集引擎。

## 当前状态

当前已完成基础骨架：

- `models.py`
  - 采集阶段定义
  - 平台画像定义
  - 执行计划定义
- `artifacts.py`
  - 采集协议化产物落盘
- `engine.py`
  - 协议化采集引擎基础结构
  - 平台规划与运行上下文

## 后续实施顺序

1. `1688`
   - 优先接管 `window.context` 相关提取链
   - 把标题、价格、主图、详情图、SKU、参数抽成结构化载荷
2. `taobao / tmall`
   - 先找页面状态对象与接口来源
   - 再从 DOM 选择器中逐步剥离价格、SKU 与图片来源
3. `asset_manifest`
   - 让下载器消费清单，不再负责猜业务结构
4. `import_manifest`
   - 让导入器消费标准结构化结果

## 原则

- 不把协议化采集继续塞回 `run_capture_task()` 大函数里
- 不做隐式兜底
- 每个平台都要有独立证据和产物
- 先证据，后执行器
- 采集协议化与发布协议化分模块维护
